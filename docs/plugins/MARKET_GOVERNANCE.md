# 市场、供应链与发布治理

## 当前实现

本机 curated-local 目录、类型化清单、只读搜索/分类、范围和许可详情、精确依赖计划、
显式权限确认、随源适配器安装登记、项目启停/版本锁、工件归档与完整性校验。
无网络分发服务、账号、付费、自动更新、第三方代码上传、远程模板执行或发布者签名。
所有状态来源是真实清单/数据库/运行记录，不展示虚构下载次数、认证或用户评价。

## 公共目录的建议审核流程（尚未实现）

草稿 → 结构/schema 检查 → 包完整性/SBOM → 权限/许可证审查 → CI 安全与功能检查
→ 数值范围与证据审查 → 签名与 staged → 发布 → 废弃/撤回/替代。

外部发布者须有独立 namespace，不允许冒用上游库/厂家名称作为“官方”身份。
标签分开：第一方适配器、第三方开发者、来源已核验、仅接口验证、解析基准验证、
实验比对；不设含混的一个“认证通过”勾号。

版本不可变：包 digest 和每个 payload 均保存。更新增加权限、外发数据、原生执行、
改变算法/输入 schema 时须重新审查；不自动替换项目已锁定版本。
撤回阻止新安装/新运行，已有结果可只读保留并标警告。受影响工程列表与修复建议
应依赖精确运行/插件锁追踪，不默默删除用户历史结果。

## 供应链

未来使用成熟 TUF 实现：root/targets/snapshot/timestamp、过期、密钥轮换和一致索引；
包可选择 OCI artifact 或普通对象存储，但 descriptor/digest 不能替代签名根。
本批不自创密码协议，也不以本地 SHA 字段宣称支持 TUF/OCI。

构建与分发的责任：
- 包含的代码、依赖、平台二进制分别记录许可证，提供实际 LICENSE/NOTICE 和 SBOM。
- Python requirement 的顶层版本锁不等于传递依赖或 wheel 哈希锁。
- 商业分发前确认主项目许可证；当前 adapter_license 为 LicenseRef-Project-Undeclared，
  不擅自给用户代码授予 Apache/MIT，也不因此向公众许诺开源/闭源分发权。
- Gmsh 原生程序/库的 GPL 及 upstream exception 和商业选项须按实际链接/包装/分发方式审查。
  放进独立进程不自动消除 copyleft 义务；本批不随发行包复制 Gmsh 二进制。
- 其他框架的 license 标签只用于初步目录说明，传递依赖另查，不能作为法律意见。

## 执行隔离待办

当前只运行源审查的第一方代码。`python -I` + 最小环境 + 工作目录 + 超时是可靠性约束，
并不禁止恶意程序读文件/联网/再起子进程。公共第三方启用前必须有真实 OS sandbox，
拒绝默认网络与宿主文件访问、限制内存/磁盘/CPU/进程、授权数据代理、签名运行镜像、
漏洞/撤回机制。市场或 Agent 不获得安装系统软件、私密令牌和自动工程审批权限。

## API 审查

POST install-plan 是无状态只读计算。POST install/enable/uninstall/invoke 均需明确意图。
所有写操作沿用本机 Host/Origin 保护，但这不是公网鉴权。暂不部署到公网或多租户。
原生运行环境在服务端管理员控制，客户端不能提交 Python 路径、shell、源文件地址。
公开运行结果只给已声明工件；stderr/stdout 不直接反射到浏览器。
