升级与备份恢复

升级到新版本、回退到上一版本，以及工程库的备份与恢复。

升级

  1. 停止正在运行的服务（在启动窗口按 Ctrl+C）。

  2. 把新版安装包解压到另一个目录。

  3. 用安装时保存在解压目录之外的那份配置文件，运行新包里的入口：

升级时会发生这些事：

  • 新程序装进 数据目录/programs/<新构建编号前16位>/，旧程序和它的环境保留不动。
  • 启动新版之前，先用 SQLite 备份接口给工程库做一份快照，放在 数据目录/release-snapshots/，并核对完整性和 SHA256。
  • 新版只有在界面和接口都检查通过后才成为当前版本。健康检查前失败会停止新进程、恢复升级前的工程库，旧版本保持为当前版本；升级过程中被强制中断，下次启动会自动从未完成的升级中恢复。
  • 工程库版本比程序支持的更新时，任何迁移之前就会拒绝启动。
  • 数据目录中的工程库、数据集、复现资料、工程证据、备份和 Agent 对话记录（数据目录/agent/）全部保留；配置文件继续使用同一份。

升级后，已保存的结果是否仍然有效

升级可能同时更新计算插件。已保存的运行记录不会被改写，也不会自动重算。平台在读取每一次运行时，把它当时使用的插件发行与当前安装的发行逐一比较：

情况界面显示是否需要处理
插件发行没有变化当前结果不需要
新发行只改了说明或显示（方法说明，参数的显示单位、换算比例或偏移，SI 单位不变），且能证明计算内容不变提示“方法说明已更新；保存结果仍有效”不需要；结果仍可用于对比和正式交付
计算相关内容有变化（包括参数的 SI 单位），或无法证明计算内容不变标为历史结果并写明原因，例如“基于旧版本方法 1.2.0（cablesim.iec60287）；当前安装版本 1.2.1”；研究页显示“方法 … 已更新（1.2.0 → 1.2.1），结果需重算”按当前方法重新运行后才是当前结果；不重算时结果保留为历史结果
研究引用的电缆型号发布了新版本“基于旧版本型号 1.0.0（……）；当前版本 1.0.1”需要采用新版本时重新运行
运行所用的插件已卸载或当前不可用“方法 …… 当前不可用”恢复安装该插件，或改用其他方法重新运行

“能证明计算内容不变”由平台比较新旧两个已封签发行中与计算有关的部分得出，不依据版本号判断。

对交付文件的影响：

  • 已导出的交付存档保持当时生成的文件，不会被改写。
  • 重新生成规格书时，若引用的运行是历史结果，封面会注明“历史结果 · ……；请重算后生成当前规格书”。先在型号设计中重新运行相应通道，再生成。
  • 已提交审核或已发布的规格书与提交时的内容摘要绑定。重新运行使规格书内容发生变化后，原提交即失效，需要重新提交审核；失效的批准记录不会填入交付文件的签栏。
  • 计算书引用的运行若为历史结果，文件中会标明版本状态；需要当前结果时先重新运行再生成。

回退到上一版本

Windows 使用 .venv\Scripts\python.exe。回退会恢复上一版程序和它的升级前工程库；回退前仍会保留当前工程库的安全副本。

回退到不含 Agent 对话服务的旧版本前，先从 release.toml 删除整个 [agent] 一节，否则旧版本会拒绝启动。

升级之后新增或修改的工程数据不在升级前快照里，回退后看不到这些数据，需要时可以从保留的安全副本中核查。存在未完成的升级或已排队的数据库恢复请求时，回退会被拒绝，先完成或取消对应请求。
