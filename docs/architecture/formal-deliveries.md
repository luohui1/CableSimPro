# 正式交付文件接口

本契约对应 issue #39 的正式规格书、计算书、载流量表和研究报告。实现位于
`backend/kernel/formal_deliveries.py`，只读取已经保存的工程与运行记录，不求解、
不生成规格书来源运行、不提交审核或批准，也不修改已有交付接口。发行安装入口见
[发行安装契约](release-installation.md)。前端可用以下接口接入现有按钮，无需新页面。

## 预览与固定来源

`POST /api/formal-deliveries/preview` 接收以下结构。示例里的 ID 与摘要须替换成
当前 API 返回的真实记录；不能用示例字符串发起工程计算。

```json
{
  "kind": "calculation",
  "source": {
    "workspace_id": "工程 ID",
    "expected_revision": 4,
    "runs": [{
      "run_id": "保存运行 ID",
      "input_digest": "完整运行返回的 64 位小写 SHA256",
      "output_digest": "完整运行返回的 64 位小写 SHA256"
    }]
  },
  "document": {
    "organization": "交付单位名称",
    "number": "CALC-001",
    "revision": "A",
    "header": "工程交付文件",
    "footer": "完整数据与计算来源见追溯页",
    "issued_on": "2026-11-16"
  }
}
```

`kind` 与来源规则：

| 类型 | 用途与来源 |
| --- | --- |
| `specification` | 产品规格书；`source.specification_digest` 必填，`runs` 留空。取 `GET /api/types/{wid}/specification?audience=internal&view=full` 的摘要，依据其中固定的结构、电气、载流量、短路、标准五通道运行。缺少所需保存来源时拒绝，不在导出期间补算。 |
| `calculation` | 一条完整保存运行的计算书，含适用范围、假设、结果、已有材料依据、关键输入和追溯。 |
| `rating_table` | 一条已有载流量表运行；保留原工况、回路、单位、口径和缺项。普通单次研究不能冒作载流量表。 |
| `research_report` | 同一工程内 1–16 条明确选择的完整保存运行，按运行逐一呈现方法、条件、结果及已有比较/结论。不会生成不存在的研究结论。 |

后三种使用 `source.runs`，不接受 `specification_digest`。计算书与载流量表只选一条
完整运行；同名结果的不同工况不会相互覆盖。运行必须属于所选工程、已完成且通过
输入/输出完整性校验；`partial` 的缺项保留原状态。历史运行明确保留历史状态，不能
借当前方法版本或默认参数替换。验证过的原生温度场仍执行原有收敛证据门禁；没有
合格证明或有效比较记录时拒绝正式导出，IEC 轨迹按已有契约区分，不伪称 FEM。

运行来源 API 必须使用 `?view=full`，例如
`GET /api/workspaces/{wid}/studies/{sid}/runs/{rid}?view=full`。较轻的 `detail` /
`evidence` 投影不包含完整输入快照，不能用来重算完整摘要。

## 单位信息与签栏

`document.organization`、`number`、`revision` 必填，分别最多 120、80、32 字符；
`header`、`footer` 可选，各最多 160 字符。`issued_on` 是可选的文件签发日期，严格
使用 `YYYY-MM-DD`；不把它当作签字日期。缺省不填当前日期。元数据不接受控制字符。

可选 `logo_data_uri` 为 `data:image/png;base64,...` 或 `data:image/jpeg;base64,...`。
后端核验真实图片格式，限单帧、512 KiB、每边 2400 像素；不读取 URL 或服务器路径。
没有提供标志时不伪造单位标志。单位信息与标志进入封面，PDF 每页有单位、编号、
版次和自定义页眉页脚；Excel 的工作表页眉页脚也包含这些内容及页码。

Excel 自身限制每个页眉/页脚的总字符数，格式控制符也占用容量。渲染器为控制符
预留空间，组合后的页眉超过 220 字符或页脚超出剩余容量时返回
`FORMAL_XLSX_HEADER`，要求缩短元数据，不静默截断。PDF 不受这一 Excel 容量限制。

四个独立签栏为设计、校核、审核、批准。请求体不接受任何签名字段。当前已有
规格书批准记录只能够填写“批准”，并核对原提交、工程修订、规格书摘要、输入、
来源与发布排除范围一致；失效或错范围的记录拒绝采用。设计/校核/审核没有独立
记录时留空。修订作者、操作人、要求评审、来源核对或 AI 提案都不充当签名。
独立运行导出也不自动继承型号规格书的批准。签栏附有原证据索引，可在追溯数据中核查。

## 共享预览模型

预览返回 `schema: cablesim.formal-delivery/1`，包括：

| 字段 | 含义 |
| --- | --- |
| `metadata` | 实际用于文件的完整单位与文件元数据 |
| `source_identity`、`state` | 固定的工程、修订、运行摘要和保存状态 |
| `signatures` | 四栏及真实记录索引；没有记录的姓名、日期与索引为 `null` |
| `sections` | 依次排列的正文和追溯章节；追溯总在正文之后 |
| `tables` | 唯一表格集合；章节只引用表 ID，不重复存储表格 |
| `sources` | 来源身份、类型、完整内容摘要和读取接口；预览省略较大的 `payload` |
| `coverage` | 原文完整归档、未声明单位的输入、未展开数组及可见表范围 |
| `source_digest`、`model_digest` | 完整来源集合和完整文件模型的规范 JSON SHA256 |

表格单元格的 `value` 保持来源类型和值，`raw_text` 是完整 JSON 数字原文或原字符串。
`value_ref` 以 `source_id` 和 RFC 6901 `pointer` 指向完整来源；工程数值必须有
对应索引。`unit_ref` 指向保存的单位字段或明确的宿主领域单位契约，不根据参数名称
猜单位，也不补当前默认值。未明确单位的输入保留在完整快照与覆盖说明中，不冒充
已知单位的正文工程量。不同原始值不会因展示舍入而合并。正文显示使用独立的 `presentation` 策略及每个数值的 `display`（显示值、显示单位、scale、offset、quantum、rounding），完整源值及源单位永远留在 `value/raw_text/unit` 和追溯页。

正文使用方法的保存名称，原始插件标识仅出现在追溯部分。追溯记录区分算法版本与
发行版本，并保留发行摘要、完整输入/输出摘要、数据来源原文、适用范围和保存的
验证等级。已有验证等级不等同工程批准，不提升缺失或较低等级的证据。
标识识别包含冻结清单中的其他发布者及大小写显示变体；含标识的保存原文完整移入
追溯，不改写原文后再将其冒称逐字引用。

## 文件导出

`POST /api/formal-deliveries/export` 使用完全相同的预览请求，另加：

```json
{
  "format": "pdf",
  "expected_model_digest": "本次预览返回的 model_digest"
}
```

上段是新增字段，不是独立请求。`format` 支持 `pdf` / `xlsx`，默认 `pdf`。
文件生成前重新核对完整模型，生成后再检查来源及签核记录；预览后改了元数据或
运行/工程/批准状态，或渲染期间发生变动，会返回 `409`，不返回旧范围文件。

成功响应直接返回文件字节，带正确 MIME 和 UTF-8 `Content-Disposition`，以及：

| 响应头 | 校验对象 |
| --- | --- |
| `X-Artifact-SHA256` | 实际响应文件字节 |
| `X-Delivery-Source-SHA256` | 完整来源集合 |
| `X-Delivery-Model-SHA256` | 完整共享模型，等于请求固定的预览摘要 |
| `Cache-Control: no-store` | 文件与 API 预览不进入共享缓存 |

错误体沿用 `{"detail":{"code":"...","message":"..."}}`；请求结构错误使用现有
FastAPI `422` 校验结构。来源或修订改变一般为 `409`；缺少正式交付数据、无法完整
排版或超过界限为 `422`。上限为完整来源 32 MiB、可见表 6000 行、单份文件 64 MiB；
超限要求缩小选择，不截断输入、表格或附件。

### PDF

封面包含单位信息、文件编号、版次及四签栏；正文表格重复列头，单位与数值不拆开，
长原文连续分页，追溯页独立起页。截面图只使用已保存且支持的圆形轮廓；不把不支持
的几何替换成猜测的圆。字体嵌入，单位中的负号与上/下标保持原 Unicode，缺字明确
拒绝。数据模型与字体许可作为附件：

- `formal-model.json`：完整规范 JSON，包含所有 `sources.*.payload`、输入快照、
  输出、冻结方法清单、来源和模型摘要。
- `DROID_NOTICE.txt`、`bitstream-vera-license.txt`：随嵌入字体分发的原始许可。

### Excel

“文件信息”工作表包含单位、标志、编号、版次与四签栏；正文和追溯章节分工作表，
有表头、单位、打印页眉页脚、冻结窗格与换行。长说明跨行合并显示，原单元格内容
保持完整。单元格文字始终作为字符串写入，`=` 开头的来源文字也不会变成公式。

工程表正文主列按已声明的工程单位与 GB/T 8170-2008 修约规则显示；原始数值文本保存在“追溯数值”的 `raw_text` 与隐藏“追溯原文”，避免 Excel 的显示与另存精度损失。另有：

- “追溯数值”：每个工程数值对应一行，包含原表/行/列身份、可见单元格地址、
  `raw_text`、可用于分析的 `numeric_value`、单位与来源索引。写入 OOXML 数值
  字面值时保留完整原始数字，不使用会损失末位的 16 位格式化。
  超过安全整数范围的整数保留文本并标为 `int-text`；不强转成不精确的 Excel 数值。
- “追溯原文”：隐藏的机器可读归档页，可在表格软件中取消隐藏；列为
  `chunk_index`、`json_chunk`。按顺序拼接第二列，得到与 PDF 附件相同的完整
  规范 JSON，每片最多 30000 个 Unicode 字符。可见的追溯章节并不隐藏。

“追溯数值”列的前十三列固定为 `table_id,row_id,column_key,sheet,cell,raw_text,numeric_value,unit,source_id,pointer,unit_source_id,unit_pointer,numeric_kind`。启用工程显示时附加 `rendered_text,display_text,display_unit,scale,offset,quantum,rounding,display_policy`。
分析数值列不取代原文列；用户在 Excel 中编辑或另存后应重新核对来源与文件摘要。

## 按工程或显式系列成员批量导出

`POST /api/formal-deliveries/batch/preview` 接收 `scope` 与 `items`。每个条目
复用前述单文件预览请求，另加机器可读 `key` 和 `formats`，不嵌套另一层请求：

```json
{
  "scope": {
    "kind": "project",
    "workspace_id": "工程 ID"
  },
  "items": [{
    "key": "calculation",
    "kind": "calculation",
    "source": {
      "workspace_id": "工程 ID",
      "expected_revision": 4,
      "runs": [{
        "run_id": "保存运行 ID",
        "input_digest": "完整运行返回的 64 位小写 SHA256",
        "output_digest": "完整运行返回的 64 位小写 SHA256"
      }]
    },
    "document": {
      "organization": "交付单位名称",
      "number": "CALC-001",
      "revision": "A"
    },
    "formats": ["pdf", "xlsx"]
  }]
}
```

`items` 可追加任意已支持文件类型，各条目仍遵守单文件的来源、单位、签栏与
正式交付门禁。批量操作不补算、不审批，也不自动选择最新运行。

### 选择范围

| scope | 选择与校验 |
| --- | --- |
| `project` | `workspace_id` 指当前已有工程，全部条目必须属于这一工程。 |
| `series` | 调用方提供 `series_name` 和 `workspace_ids`，明确选定本次归为一组的工程成员；成员列表不得重复，必须与条目的实际工程集合完全相等。 |

系列范围示例，用于替换上述请求的 `scope`：

```json
{
  "kind": "series",
  "series_name": "本次选定的系列交付",
  "workspace_ids": ["第一个工程 ID", "第二个工程 ID"]
}
```

当前型号方案的 `type_families` 是同型号方案/发布谱系，不等同跨规格商业系列。
现有系列导入记录没有稳定的系列到工程关联；本接口因此明确接受用户选定成员，
不根据型号前缀、制造商或来源原文猜归属，也不写入 T3 的系列数据模型。响应与
ZIP 清单在系列范围中强制记录 `membership_source: explicit_workspace_ids`，
不将命名分组冒称已有登记系列。该字段由服务器生成，请求不得自行提供。

同一工程的所有条目必须使用相同 `expected_revision`；历史运行是否适合交付，
继续由单文件来源校验判定。系列声明了未使用成员，或条目带入未声明工程时均拒绝。

### 条目、摘要与文件路径

`key` 为 1–40 个 ASCII 字母、数字、下划线或连字符，首字符须为字母或数字，
忽略大小写后必须唯一。`formats` 为 1–2 个不重复的 `pdf` / `xlsx`，顺序保留。
最多 16 个条目、32 个交付文件；同一份文件编号可用于不同条目，不会覆盖。

预览返回 `schema: cablesim.formal-batch/1`，主要字段如下：

| 字段 | 含义 |
| --- | --- |
| `scope` | 实际校验的工程或显式系列成员范围 |
| `items` | 按请求顺序排列，含 `index/key/kind/title`、规范化 `source/document`、完整 `source_identity`、模型与来源摘要、无大 payload 的来源描述符、格式与计划文件路径 |
| `file_count` | PDF/XLSX 文件数量，不包含 `manifest.json` |
| `source_bytes` | 各条目完整 `sources` 规范 JSON 字节数之和；同条目两种格式只计一次，不同条目仍各计一次 |
| `batch_digest` | 除本字段外完整批量预览的规范 JSON SHA256，固定范围、成员、顺序、元数据、来源、格式、路径和每项模型摘要 |

文件路径固定为 `001-<key>/<kind>.<format>`，序号从 1 开始。例如
`001-calculation/calculation.pdf`。路径不采用文件编号或任意用户路径，避免同号文件
覆盖、跨目录写入和大小写冲突。原文件编号仍完整保存在 PDF/XLSX 元数据和清单中。

规格书的请求固定其规格书摘要，实际来源运行由规格书确定；因此清单同时保留
请求 `source` 和模型的 `source_identity`，后者包含实际五通道运行及输入/输出摘要，
不能只凭一个规格书摘要省略其真实来源。

### 整包导出与清单

`POST /api/formal-deliveries/batch/export` 使用完全相同的批量预览请求，另加
`expected_batch_digest`，值为本次预览返回的 `batch_digest`。成功返回
`application/zip`、UTF-8 下载文件名以及：

| 响应头 | 校验对象 |
| --- | --- |
| `X-Artifact-SHA256` | 实际 ZIP 响应字节 |
| `X-Delivery-Batch-SHA256` | 固定的批量预览摘要 |
| `Cache-Control: no-store` | 批量文件不进入共享缓存；单份和批量预览也明确使用此头 |

ZIP 根目录的 `manifest.json` 包含完整批量预览和额外的顶层 `files` 清单。每个
文件记录条目序号、键、类型、格式、路径、实际 `bytes/sha256`、模型/来源摘要、
请求来源、实际 `source_identity` 和含读取 API 的来源描述符。每份 PDF/XLSX
仍各自携带完整原始来源，批量打包不删改其内容。清单本身不列入交付文件清单，
ZIP 的实际摘要放在响应头，避免清单摘要引用自身。

重新构建的有效批量计划与预览摘要不同时返回 `FORMAL_BATCH_CHANGED`（409）；
摘要包含元数据、成员、顺序、格式、来源和签核。若固定的来源已经失效、修订不符，
或某一条目已不能生成，则在构建阶段返回下述 `FORMAL_BATCH_ITEM_FAILED`，
保留原始来源错误，不能只按一个批量错误码判断所有冲突。所有条目生成完毕后，
会重新构建并核对**全部**
来源模型；即使第一项在最后一项渲染期间才发生变化，也拒绝整个 ZIP。单条目
不能生成时返回 `FORMAL_BATCH_ITEM_FAILED`，保留其原 HTTP 状态和 `cause`，
并附条目序号、键、类型、工程和失败阶段。请求结构错误仍为 FastAPI 的 422。
生成后的重新核验如发现来源失效，响应统一为 409，原失败状态保留在 `cause_status`。
整包累计超限、清单或 ZIP 归档失败为 `FORMAL_BATCH_ARCHIVE_FAILED`，带
`stage: archive`、`cause_status` 和原 `cause`，不将全局失败归给某个条目。
任何失败都不返回部分文件，不跳过条目，不改成使用另一条运行。

完整来源累计最多 128 MiB；全部 ZIP 未压缩内容（含 `manifest.json`）最多
128 MiB。既有单份 32 MiB 来源、6000 行可见表、64 MiB 文件门禁继续适用。
超限明确拒绝并要求缩小选择，不通过截断文件、来源或清单规避限制。


## 工程正文呈现（新增审核要求）

此步骤仅作用于交付文件的显示层，不改变完整来源、求解结果、合格判定、签审或任何已保存快照。正文与 Excel 工程主表使用统一的 `cablesim.engineering-display/1` 展示政策。依据 **GB/T 8170-2008 第 3.2、3.3 条**，从保存 JSON 数字原文在十进制中只做一次单位换算与半偶修约（ties to even）；禁止先修约 SI 再换算，也不得反写运行记录。

| 工程量 | 正文单位 | 显示精度 |
| --- | --- | --- |
| 允许电流 | A | 整 A |
| 绝对温度 | °C | 0.1 °C；K → °C 减 273.15 |
| 电缆外径、直径、间距 | mm | 0.1 mm |
| 层厚 | mm | 0.01 mm |
| 截面 | mm² | 最多四位有效数字 |
| 单位长度质量 | kg/km | 整 kg/km |
| 单位长度电阻 | Ω/km | 四位有效数字 |
| 其他已声明工程量 | 原适用单位（有专用换算时按专用规则） | 最多四位有效数字 |

温差及温度系数不当作绝对温度平移。每个正文数值都保留原始 JSON 原文、单位及来源 JSON Pointer；追溯页逐项给出显示数值、十进制换算系数、偏移量与修约间隔，Excel “追溯数值”同时保留 typed numeric 副本与原值原文。校验器独立按原值复算并比对显示，不信任导出侧自己写出的显示信息。
