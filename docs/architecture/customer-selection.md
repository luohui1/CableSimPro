# 目标电流问询选型

J4复用研究的领域截面、负荷和方法配置，在`StudyDefinition.modules.selection`中保存候选范围。宿主只展开完整候选输入和整理插件输出，不按截面积外推。界面入口为研究的“问询选型”；新建研究也可以直接选择“客户问询选型”。

## 型号版本

发布安装随附`backend/kernel/data/huayuan_yjv22.json`（系列`huayuan.yjv22.8.7-15.three-core`，版本1.0.0），含35、50、70、95、120、150、185、240、300、400 mm²十个华远YJV22规格。厂家字段摘自公开网页“四、结构尺寸”对应行；R20独立标记GB/T3956表2标准上限，原件哈希、网址、获取日期及Zotero条目保存在包内；网页/标准全文不入库。`backend/kernel/model_series.py`只转换SI和通过`POST /api/domain-cable-models`导入，不计算结构或载流量，不读取开发库、归档原件或联网服务。相同内容重试复用ID，来源和包SHA256进入候选快照。

原始十个候选仍为`incomplete/confirmed=false`；包内另存有版本、有出处的参考问询工程参数，显式绑定当前IEC `model-completion`能力后，计算模型为`engineering_input`，计算书列出参数依赖，不能据此批准型号或宣称厂家实测。发布种子`seed_release`首次创建三回排管400 A全系列问询、3×300土壤0.6–2.0 K·m/W共同能力扫描和独立规格书草稿；已存在且完整的发布库继续原有保留规则，不静默改写用户工程。新库三条流程以`scripts/verify_release_workflows.py`为发布门禁，首错停止。

`GET/POST /api/domain-cable-models`保存不可变的`name/version/cable_type/materials/sources/confirmed`。结构和材料采用`cablesim.domain/1`的SI类型；电压为V、截面为m²、尺寸为m、R20为Ω/m、温度为K。型号引用的全部材料必须存在，来源必须有出处。只有工程师明确确认且来源均已核对、没有演示来源、具备R20时，版本才标为`reviewed`。默认保存草稿；导入文件中的`confirmed`不会自动确认界面导入。相同内容摘要的重试返回同一版本ID，不重复入库。

公开样本未形成完整模型时，同一 API 接受 `specification`，原始记录保持 `cable_type=null` 和 `incomplete`。公开字段的 `value/unit/basis/source` 区分厂家值、标准标称值和标准上限；保留网址、版本/页码及原文SHA256。资料可以参加筛选；缺工程参数时逐字段拒绝，不使用当前型号替代。

工程师在新建问询或候选表打开“工程参数”，明确填写值、单位和出处；参考输入须主动采用。`candidate_completions[id]` 固定模型准备方法和参数，IEC `model-completion` 插件输出 `x-cablesim.engineering-model`。宿主只校验和保存工件，不推导电缆结构或电损耗。原始型号库不改写、不自动确认；研究候选标为 `engineering_input`，保存原始型号摘要、给定参数、推导值、准备插件版本及工件SHA256。失败不缓存为成功，重试仍采用同一明确输入。

8.7/15 kV 三芯 YJV/YJV22 分支采用 GB/T12706.2-2020 10.2.3 的铜带标称厚度及15%标称搭盖；纵向电阻的标准推导依赖工程师给定的连续接触等效模型，`R20=ρ20 C_LL/[πd_mean t/(1-overlap)]`，不是厂家实测电阻。也可以给定纵向 R20（Ω/m）。厂家钢带厚度优先；缺厚度时按附录 A.2.1–5、A.2.9 的假设直径和13.5表11取标称值，禁止使用实际直径代替假设直径。材料使用 IEC60287-2-1:2023表1参考值；本分支PVC保护层按该表脚注的绝缘等级口径取6 K·m/W。成缆节距、径向包络、导体构造、填充/包带热阻率、钢带间隙/磁导率和外径列示精度由工程师给定。界面提示区分方法输入范围、标准边界和TB880参考示例；没有可靠厂家范围的字段不伪造“通用典型范围”。

`DELETE /api/domain-cable-models/{id}?expected_digest=...`仅清理摘要准确且从未被任何研究版本或运行引用的草稿/资料版本，已核对版本和历史引用一律保留。型号页的结构编辑和发布流程保持由型号模块管理。

界面“导入型号版本”接受上述JSON，显示型号、版本、单位换算和出处后由工程师确认。版本保存在选型型号库，历史运行继续引用自己的原始候选快照和SHA256。它不批准研究方案，也不替代型号结构设计的发布流程。

## 完整输入与判定

`driver.minimum`为每回路目标电流A，必须为正数；`candidate_filters`按电压、导体材料及截面上下限筛选。默认仅列已核对型号；显式使用草稿演示时，页面和计算书禁止给出工程推荐。混合型号线路的替换范围尚未覆盖，明确拒绝。

预检前引用研究当前的稳态方法及完整参数，所有回路负荷改为保存的问询目标。每个候选替换完整`CableType`和所用材料，保留敷设、边界、工况及手动锁定；型号绑定产生的结构锁只对本次候选实验解除。每个候选独立计算，并保存准备输入摘要、方法清单及插件精确版本；同一精确方法版本的候选补参数合并为一次多工况插件请求，按`case_id`对应结果，失败不进入成功缓存。

### 执行复用与封签追溯

IEC 0.9.2启用现有宿主常驻进程协议，逐请求创建输入/输出目录并校验结果，数值公式不变。型号规格书五项生成复用各项刚完成的预检，正式接纳运行时仍核对当前输入摘要与插件锁；连接中断重试继续使用请求ID，不重复生成运行。

研究执行器的封签缓存只保存在当前宿主内存中，以发行清单SHA256和源码内容摘要为键，不依赖文件修改时间。每次实际启动插件前重新读取插件包及封签依赖闭包的文件字节，并核对完整模块文件/目录清单；导入方内容和模块清单不变时，不必读取无关模块的内容。内容或导入清单变化必须重新核验完整闭包。同一请求内的只读方法解析共享该请求的已核验快照，不能绕过执行前的字节检查。新增模块引起可解析导入变化、源码篡改、同版本替换发行均有回归测试。

运行`environment.seal_verification`及逐工况`evidence.seal_verification`保存`status=verified`、`release_digest`、`source_tree_sha256`、`verified_at`、`cache_hit`、`request_snapshot_reused`和核验策略；候选准备快照也保留该凭据。实际执行凭据的`request_snapshot_reused=false`，缓存命中不省略封签证据。接口路径与请求模型不变。

`python scripts/verify_release_workflows.py --performance-only --profile-preflight`使用全新临时发布库测量问询预检与首次五项规格书生成，包含首次CAD进程启动；输出`performance_measured`及5/30秒门槛结果，不冒充三条发布流程全部通过。

Windows发布种子API实测：问询预检20.442→2.005秒，五项规格书84.803→28.147秒，分别达到5/30秒目标。优化后测量串行执行，未人为预热工作进程，未清空操作系统文件缓存；这是本机单次验收值，不是跨机器延迟承诺。10个候选数值不变，推荐3×400、406.109148 A。证据保存在忽略目录`.data/acceptance/release-performance-final/`，临时库已删除。

所有指定回路的允许电流均可用时，采用其最小值，余量为允许电流减目标电流。满足/不满足按余量符号判定；方法范围拒绝保存为`not_applicable`，求解失败保存为`failed`，均不进入合格列表。插件明确报告无正载流量时标不满足，不编造0 A结果。无适用候选时只保存拒绝记录，不调用数值执行阶段。

页面先显示推荐型号、允许电流、余量和计算书按钮，三组按截面排序，不适用折叠。已核对候选和明确补全的 `engineering_input` 可以给出有条件推荐；后者在结论旁注明依赖工程参数。计算书单列“工程师给定参数”和来源工件；显式草稿研究仍不生成工程推荐。超温原因引用已保存的温度，报告不重算、不自动批准。

型号候选选型的主结论采用 `simultaneous`：所有回路共同采用相同平衡 RMS 电流，最先达到自身温限的电缆限制共同电流，其他电缆可低于温限。宿主对型号候选请求两口径；`assessment.rating_basis/rating_basis_name` 记录实际采用的口径，计算书从 assessment 读取。历史配置的 `driver.rating_basis=individual` 保留为输入记录，不能再将“其他回路固定目标负荷”的条件上限冒充共同能力；历史运行不改写，需明确重跑。新建扫描未指定口径时默认 `simultaneous`，显式选择和旧配置保留。IEC `parameters.rating_mode` 可为 `individual` / `simultaneous` / `both`；既有 `ampacity`、case=`rating` 表示逐回路条件上限，`rating-simultaneous` 表示共同能力。数量上的结构化 `rating_basis` 与默认结果选择器见[统一口径](../METHOD.md)。其他方法没有共同能力输出时保留其明确的原结果口径，不伪造支持。

共同能力先于目标负荷温度独立求解，括区初值不从目标负荷取得。目标负荷发生 `THERMAL_RUNAWAY` 时，工件保留 `operating.status=unavailable`、错误码和空温度列表，仍发布已核验的共同允许电流；不捏造运行温度。小于目标即 `not_satisfied`，原因给出“允许电流 X A < 目标 Y A”；有实际超温解时另给已保存温度。输入越界、系数有效域、插件崩溃或真正的求解不收敛仍明确失败或不适用。固定其他回路已无稳态时，辅助逐回路上限可为空并说明原因，选型主列仍显示共同能力。

保存的10 kV三回水平排管例（间距0.25 m、中心埋深1.2 m、140/160 mm管、土壤1 K·m/W、地表25 °C）中，3×300 的181.274 A是其他两回路固定400 A的条件上限；381.448 A是其他两回路固定350 A的条件上限；369.460 A是三回路等负荷能力，两种目标负荷下相同。3×400共同能力414.281 A，400 A问询余量14.281 A（3.57%）。这些数字依赖保存的厂家尺寸和工程参数，不是厂家通用载流量表。回归见 `tests/test_customer_selection.py` 与 IEC `test_three_core.py::test_simultaneous_capacity_survives_runaway_target_and_is_load_independent`。

共同电流每个试算点重新求解全部导体/屏蔽/铠装温度、电损耗、排管空气热阻和互热，括区与温限残差均通过才发布。适用边界与原方法一致；IEC 1-2 当前温度分支仍不开放反求，固定点外部损耗仍不能迭代。独立手算核验见 IEC `test_iec60287_group.py::test_simultaneous_balanced_current_matches_independent_frozen_heat_balance`。

厂家的单回路参考载流量不代替多回路排管计算。三芯热路和电损耗范围见[IEC 方法说明](../plugins/IEC60287_SINGLE_CORE.md)。热网络已降为“交叉校核参考”，只在同输入方法比较出现，后端拒绝其参与候选选型。工程参数补全不扩大 IEC 本身的适用范围。

新建问询保存目标电流、候选摘要和敷设模板。研究专用型号列表也包含可补参数的8.7/15 kV三芯资料；`POST /api/design/study-workspaces` 可以提交固定的 `candidate_completion`，成功后才创建工程，失败保留具体字段错误。型号页接口独立。土壤和管道由敷设管理；模板工况仍标为演示，须换成项目事实。

显式选择草稿候选只允许数值校核，不能把草稿批准为已核对型号。110 kV YJLW03 规格缺导体直径或成品外径时，型号 API 的 `display_status` 为“厂家尺寸缺”；该状态不改变不可变资料摘要。

浏览器场景脚本为 `frontend/scripts/verify-research-refinement.mjs`，从新建问询、选择真实型号、补工程参数到实际下载记录操作和耗时。API集成证据不能代替浏览器流程耗时。计算书展示每芯 Rc/T1、整缆 T2/T3、λ1/λ2 及逐芯损耗。

## 失败与历史

输入校验失败定位具体字段；后端资料校验返回文件内字段路径。运行请求使用UUID，运行期间屏蔽重复操作；连接中断时保留保存输入和请求ID，刷新后可重试同一请求读取服务端保存状态。超时、崩溃和环境缺失沿用通用插件执行状态，不将失败候选当作不满足或成功。历史快照只读，变更后的输入必须重算，当前计算书不能引用旧输入。

IEC多回路电磁边界、外部λ工件及拓扑见[接地拓扑](electrical-topology.md)；温度场报告还受[收敛门禁](temperature-field.md)约束。
