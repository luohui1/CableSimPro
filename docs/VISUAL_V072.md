# 0.7.2 工程视觉资产与双模式界面

## 实际改动

- 浅色入口采用电缆剥切主图、敷设/资料配图与两个工作模式按钮。最近工程来自数据库，不加入虚构业务指标、认证或客户案例。
- 工程图随仓库交付，页面不依赖外部图片或字体服务。图片失败时有描述性降级，不影响任务入口和计算。
- 专业工作台减少重复项目栏，重组模型、参数检查和结果。电缆、敷设、资料入口使用真正的本地图片，不是 CSS 占位圈。
- 智能工程流仍使用共用工程会话。初始状态提供工作过程配图；有提案后优先显示参数差异和审批，保留失效保护。
- 实时三维使用环境照明、导体端面线股和屏蔽外观细节。装配、分层、隐藏层与米制 GLB 继续使用原工程定义。

## 配图与计算严格区分

`frontend/public/engineering/` 的三幅图片由 `scripts/visuals/scene.ts` 程序化创建。它们是原创建模的教学示意，不是厂家产品图、当前工程快照、有限元结果或产品认证。土壤显示块不是新增回填分区或沟壁求解。

`frontend/src/visual-assets/cableAppearance.ts` 增加的线股与绕制细节仅在显示场景中。绞距、根数不是制造参数，不能据此生产；它们不改变六层等效半径、不传入损耗/热计算，也不进入当前六层工程 GLB 导出。模型导出仍携带原输入与单位。

不复制此前概念图中的虚构“标准通过”、复杂沟壁校核、110 kV/220 kV 项目或企业统计。不新增任何物理求解、标准符合性或真实云端 OCR/Agent 联调能力。

## 生成与验证

在安装了锁定前端依赖和 Playwright Chromium 的环境运行：

```sh
cd frontend
npm ci
npx playwright install chromium
cd ..
node scripts/render_visual_assets.mjs
node scripts/test_visual_geometry.mjs
```

图片生成使用无网络页面、原创 Three.js 场景、程序化土壤材质与原电缆几何。无需 GPU 硬件，可使用 Chromium 软件 WebGL；受策略禁止 WebGL 的主机不能生成，应使用已提交资产。生成失败必须失败退出，不能用旧图冒充新图。

每次更改场景，应重新生成三图，审查后一起提交。`manifest.json` 说明来源；不随包分享字体文件或第三方商业素材。

新增浏览器检查：本地图片加载、缺图降级、无外部图片请求、双模式切换、有效结果、GLB 六层尺寸、浅色工作台自动无障碍规则、窄屏溢出。已有后端/浏览器测试继续运行，不以新界面截图替代交互验收。

`node scripts/test_visual_geometry.mjs` 检查铜/铝、三个截面积与三种显示模式共18个配置，验证工程半径和显示网格的有限性。自动对比度检查不是全应用无障碍认证。
