## 图片来源与导入

三个内置槽位：电缆结构、直埋敷设、资料核对。现有 PNG 是仓库原创
Three.js 场景的输出；运行页面读取压缩 WebP。说明图具有独立标题、替代文本、
“非计算结果”标注和加载失败回退，图片失败不阻止工程入口。

`frontend/src/engineering-visuals/catalog.json` 为页面和完整性检测共用清单，
记录字节校验值、源文件校验值、来源声明、权限说明及用途。
来源声明是维护者登记的数据，不是生成服务的密码学签名。

用户授权在开发中使用 Grok-image。工具目录显示其已安装，但本轮会话没有
暴露调用端点，因此没有调用 Grok-image、没有异步生成任务，也没有验证
“无限生成”或费用条件。没有凭名称编造一个 Grok API 或向外部发送企业资料。
本轮内置图的 provider 均为 `procedural-threejs`，没有冒充模型输出。

以后取得生成输出文件时，可在开发环境执行：

```sh
python scripts/import_visual_asset.py /path/to/output.png \
  --slot cable --title '电缆分层结构' --alt '电缆剖切说明图' \
  --provider grok-image --source-id JOB_ID \
  --rights-note '填写真实的使用授权依据' \
  --review-note '确认仅作结构说明，不含未经验证的计算结论' \
  --approve-illustration
python scripts/check_visual_assets.py
```

该命令不调用生成服务。它只接受本地静态 PNG/JPEG/WebP，限制大小和像素数，
校正方向、合成透明通道、去除图像元数据并压缩；拒绝把带令牌的下载 URL
写入来源字段。只允许三个说明槽位，不能写入温度场、计算结果或任意路径。
发布前仍需检查具体图片内容、权利和工程表达，不能把自动缩放当作审核。

重建内置配图：`node scripts/render_visual_assets.mjs`。
重新压缩内置图：`python scripts/prepare_builtin_assets.py`。
不同 Pillow/libwebp 版本可能改变编码字节；必须同步更新清单，不绕过校验。

## 验收

- 原有后端、跨浏览器、Windows 回归保留。
- 新增配图加载、断图回退、无外部请求、无自动建工程、审查后的真实模型／结果、
  GLB 只含工程层、1440×900 可读性、资料入口与移动端检查。
- 资产导入测试覆盖显式审核、槽位限制、签名 URL 拒绝、透明通道、非图像拒绝、
  校验和与远程路径拒绝；原始图不被修改。
- 在实际浏览器页面上执行 axe 自动检查；这不是全应用人工无障碍认证。
- 本地浏览器 HTTP 导航被环境策略阻止，真实界面验收使用 GitHub Actions；
  不使用静态截图或模拟数据冒充端到端测试。
- Windows 的 deviceScaleFactor 是浏览器模拟，不是人工修改 Windows 系统 DPI。

## 未扩大的能力

没有新增求解器、COMSOL、有限元、标准认证、真实云端 Key 成功率或无限自主
Agent。允许载流量等数值仍由既有工程工具求出。企业资料与密钥不提交公开仓库。
