## 安装与启动

### 端口被占用

| 端口 | 用途 | 处理 |
| --- | --- | --- |
| 8100 | 平台的界面和全部接口 | 先确认是否已经启动过本程序。确需更换时，修改 `release.toml` 的 `[server] port`；从源码运行时执行 `python scripts/run_demo.py --port 8101`，改用 `http://127.0.0.1:8101/`。 |
| 8111 | Agent 对话服务（只监听本机） | 修改 `[agent] port`（须不同于 `[server] port`），或设置 `[agent] enabled = false` 暂不启动 Agent。 |

端口被占用时程序在改动数据之前就停止启动，不会自动改用其他端口。

### Windows 提示路径过长

安装程序按实际文件逐个检查路径长度，超出 260 字符限制时拒绝安装。把 `storage.data_dir` 改为更短的目录（例如 `D:/CableSimPro-data`）后重新安装，不需要修改系统策略。

### 提示同一数据目录已有实例在运行

一个数据目录同时只能运行一个实例。先关闭已经运行的实例（在其启动窗口按 Ctrl+C），或为第二个实例配置另一个数据目录。

### 启动过程中页面或接口返回“正在启动”

启动完成前，工程接口一律返回 `503 RELEASE_STARTING`，避免在仍可能回退的时间窗口里写入工程数据。等待启动窗口提示服务就绪后刷新页面。

### 杀毒软件拦截随包的 Node.js

安装或启动时提示 Agent 对话服务无法运行，通常是杀毒软件拦截了 `runtime/node/` 中的 `node.exe`。在杀毒软件中信任程序目录后重新启动；暂时不用 Agent 时，在 `release.toml` 中设置 `[agent] enabled = false`。见 [Agent 对话服务](../../install/agent/#故障排查)。

## 原生依赖与插件

### 三维视图或规格书提示缺少 CadQuery

三维实体、STEP 导出和规格书中的结构计算需要原生 CAD 依赖。

- **离线安装包**已自带这些依赖。仍出现该提示时，说明安装不完整，重新解压安装包并安装。
- **从源码运行**时，在启动器创建的环境中安装原生依赖后重新启动：

```powershell
.\.data\release\venv\Scripts\python.exe -m pip install -r plugins/requirements-native.txt
```

```sh
.data/release/venv/bin/python -m pip install -r plugins/requirements-native.txt
```

### 插件封签或摘要不一致（接口返回 409）

每个插件发行都有封签，记录清单、源码、依赖和展示资源的摘要。运行前平台逐项核对，不一致时拒绝执行并返回 409，常见错误码如下：

| 错误码 | 含义 |
| --- | --- |
| `PACKAGE_DIGEST_MISMATCH` | 插件文件或运行依赖与封签记录不一致 |
| `HOST_DEPENDENCIES_MISMATCH` | 插件依赖的宿主源码与封签记录不一致 |
| `PLUGIN_ASSET_DIGEST_MISMATCH` | 插件展示资源与封签摘要不一致 |
| `RELEASE_CHANGED` | 核验期间文件发生变化 |
| `MODEL_INTEGRITY_ERROR` | 最新发布型号的内容摘要不一致 |

处理方法：保留完整报错，交给维护人员核对程序和插件版本，必要时重新安装同一发行包。**修复之前不要通过修改工程参数绕过**：封签不一致意味着无法证明计算使用的是经过验证的代码。

## 计算与仿真

### 超算未配置或不可用时，哪些功能仍可用

| 不可用 | 仍然可用 |
| --- | --- |
| 有限元温度场、暂态、电热耦合、批量仿真等声明为只在超算运行的方法，拿不到新结果 | IEC 60287 等解析计算、参数扫描、输入编辑、标准核对、正式交付导出、备份恢复；已保存且校验通过的仿真结果可以查看 |

只在超算运行的方法遇到超算未配置时，运行前预检会提示配置，不会改到本机计算。配置方法见[仿真计算环境](../../install/hpc/)。

### 预检提示超出方法适用范围

每个方法只在其声明的适用范围内计算。预检会逐条列出超出范围的原因（例如截面、排列或敷设方式不在方法覆盖范围内），这时不能运行。调整输入使之落在范围内，或改用覆盖该工况的方法。各方法的范围见[方法清单](../../methods/catalog/)。

### 结果标为历史结果

保存结果之后，输入、引用的型号版本或方法发行发生了变化。历史结果保留原样，可以查看和比较；需要当前结果时重新运行。升级插件后的具体情形见[升级后已保存的结果是否仍然有效](../../install/upgrade-restore/#升级后已保存的结果是否仍然有效)。

## 标准核对

标准核对把型号的结构尺寸与导体电阻逐项与产品标准比较，每一项的判定分为以下几种：

| 判定 | 含义 | 处理 |
| --- | --- | --- |
| 满足 | 有完整输入和标准依据，判定满足 | 无 |
| 不满足 | 有完整输入和标准依据，判定不满足 | 点“定位结构层”修改结构，保存后重新核对 |
| 待补数据 | 判定所需的数值缺失，例如材料类别、屏蔽或铠装参数；或标准要求按出厂实测值判定（如绝缘最薄点），设计值不能代替 | 在型号设计中补齐有来源的输入后重新核对；需要实测值的项目在取得出厂检验记录后录入 |
| 未覆盖 | 标准依据库尚未收录该条款或版本，依据栏显示“本库暂未收录” | 由工程师按标准原文人工核对；软件不给出判定，**不能视为满足** |

不适用于本型号结构的条款不参与判定，收在“要求与标准”的“不适用条款”中。在“规格书 → 审核与发布”中，这些问题按“需要工程师补输入”“需要出厂实测值”“标准依据未覆盖”“需要人工批准”分组列出。

标准核对运行失败时，界面显示该次运行的实际错误和缺失字段的位置，按提示补齐输入即可。核对结论与人工批准分开记录，核对通过不代表型号已审核或发布。

## Agent 与模型

### 没有配置模型

Agent 页提示“还没有配置 AI 模型”，发送消息会被拒绝，不调用任何服务、不产生结果。在“设置 → AI 模型”中填写服务地址、模型名和密钥并测试连接。型号、计算、仿真、交付等其余功能不依赖模型。见[接入模型](../../install/model/)。

### Agent 页显示“Agent 对话服务未连接”

对话服务没有启动成功或已经退出。查看启动窗口中的原因（端口占用、杀毒软件拦截等），处理后重新启动程序。其余功能不受影响。

### 模型连接失败或超时

模型请求由平台进程发出。确认服务器能访问模型服务地址，防火墙或代理放行平台进程的出站连接；网络较慢或模型较大时，在“设置 → AI 模型”中调高单次请求超时。

## 交付文件

### 下载了 PDF，是否代表已经审核或发布

不代表。正式交付文件只呈现已保存的运行和型号，下载或导出不会提交审核，也不会批准或发布型号。审核与发布在型号设计的“审核与发布”中由人完成并单独记录。见[正式交付文件](../../guide/deliverables/)。

### 签栏为什么是空的

设计、校核、审核、批准四个签栏只填写真实匹配的签核记录。目前只有已批准、且与本次规格书内容一致的型号批准记录可以填入“批准”栏；其他签栏没有独立记录时保持空白，由人工签署。修订作者、操作人或 Agent 提案都不充当签名。

### 规格书封面写着“历史结果”

规格书引用的运行在生成后输入或方法发行已变化。在型号设计中重新运行对应通道，再重新生成规格书。
