离线安装包自带 Agent 对话服务。安装并[接入模型](../model/)后即可在工作台使用 Agent 对话，安装和运行过程均不需要联网，也不需要系统中预装 Node.js、npm 或 Python。Agent 的用法见 [Agent 的用法和边界](../../guide/agent/)。

## 随包内容

| 目录 | 内容 |
| --- | --- |
| `runtime/node/` | 固定版本的官方 Node.js 24.22.3，只含解释器和许可证文件，不含 npm、npx、corepack，安装后不能再安装或更新软件包。版本、下载地址与 SHA256 固定在构建清单中。 |
| `agent/` | Agent 对话服务（边车进程）：对话服务源码、9 份 Agent 技能、预构建的对话页面，以及运行所需的生产依赖。 |

两个目录的每个文件都记录在发行清单 `release-manifest.json` 中，计入构建编号；文件损坏会阻止安装或启动。第三方许可汇总在 `THIRD_PARTY_NOTICES.txt`。

Linux 版的 Node.js 还要求系统提供兼容的 glibc 和 libstdc++。构建时实测的最低 glibc 版本写在 `runtime/node-runtime.json`，安装前自动核对。

## 启动与关闭

`release.toml` 的 `[agent]` 一节控制对话服务：

```toml
[agent]
enabled = true   # false：完全不启动对话服务
port = 8111      # 对话服务的本机端口，须不同于 [server] 的 port
```

- 启动程序先启动平台，再启动对话服务；退出时两者一起停止。Windows 上用 Ctrl+Break 通知对话服务先关闭会话再退出。
- 对话服务只监听 `127.0.0.1:<port>`。浏览器只访问平台端口下的 `/agent-app/`（对话页）和 `/agent-sidecar/`（平台转发），内网用户不需要直接访问 8111 端口。
- 对话服务是**可选进程**：没有启动成功时，型号、计算、仿真、交付等其余功能照常可用，启动窗口和 Agent 页都会写明原因。
- 端口被占用时，启动程序在改动任何数据之前就明确失败，并提示修改 `[agent] port` 或关闭 Agent。
- 对话服务异常退出后不会自动重启，工作台其余功能继续可用；重新启动程序即可恢复。
- 对话记录保存在 `数据目录/agent/`，随数据目录一起保留。它不在工程库备份（`workspace_db.py backup`）的范围内，需要保留时一并备份这个目录。

## 模型只需配置一处

对话服务**不接触任何模型密钥**：它只向平台查询当前模型名，模型请求由平台加上密钥后转发。平台按以下顺序确定使用哪个模型（Agent 与其他 AI 功能共用）：

| 优先级 | 来源 | 密钥保存位置 |
| --- | --- | --- |
| 1 | 界面“设置 → AI 模型”中保存的配置 | 操作系统凭据库（Windows 凭据管理器、Linux 密钥环），页面读不回 |
| 2 | `release.toml` 的 `[model]`，或环境变量 `CABLESIM_LLM_BASE_URL`、`CABLESIM_LLM_MODEL`、`CABLESIM_LLM_API_KEY` | `[model]` 的 `api_key_env` 所指的环境变量（默认 `CABLESIM_LLM_API_KEY`） |
| 3 | 环境变量 `CABLE_STUDIO_MODEL_BASE_URL`、`CABLE_STUDIO_MODEL_ID`、`CABLE_STUDIO_MODEL_API_KEY` | 同名环境变量 |

规则：

- `[model]` 的 `base_url` 和 `model` 都留空时，这一节不指定任何连接，环境变量 `CABLESIM_LLM_*` 照常生效。
- 只要写了 `base_url` 或 `model` 其中一项，整个连接就以 `[model]` 为准，密钥只取 `api_key_env` 所指的变量；该变量没有设置就视为没有密钥，不会借用其他来源的密钥。
- 服务地址、模型名和密钥须来自同一个来源，不同来源的值不会拼在一起。
- 没有配置模型时，Agent 页显示“还没有配置 AI 模型：在‘设置 · AI 模型’里填写……”，发送消息会被拒绝，不调用任何服务，也不产生任何结果。

配置方法见[接入模型](../model/)。

## 安全边界

- **只在本机通信**：对话服务只监听 127.0.0.1，API 同时校验令牌和请求的主机名。
- **一次一密**：平台与对话服务之间的令牌在每次启动时随机生成，只存在于这两个进程的环境中；启动程序自身和它启动的其他进程都拿不到，也不写入配置、日志或文件。
- **拿不到密钥**：对话服务进程的环境变量按白名单设置，任何服务商密钥、代理设置和 `NODE_OPTIONS` 都不会传入。
- **写操作须人工接受**：Agent 的每一次写入都是提案，须由人在对话中接受，详见 [Agent 的用法和边界](../../guide/agent/)。

## 安装与升级时的检查

- 安装时实际运行一次随包的 Node.js；失败时提示检查杀毒软件，或在 `release.toml` 中关闭 `[agent]`。
- Windows 安装前的路径长度检查覆盖 `agent/` 与 `runtime/node/`。
- Linux 安装前核对 Node.js 要求的最低 glibc 版本。
- **回退到不含 Agent 的旧版本前**，须先从 `release.toml` 删除 `[agent]` 一节：旧版本不认识这一节，会拒绝启动。回退方法见[升级与备份恢复](../upgrade-restore/)。

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 安装时提示随包 Node.js 无法运行 | 杀毒软件拦截了 `runtime/node/` 中的 `node.exe` | 在杀毒软件中信任程序目录（`数据目录/programs/<构建编号前16位>/`），然后重新安装；暂时不用 Agent 时，在 `release.toml` 中设置 `[agent] enabled = false` |
| 启动时提示 Agent 端口被占用 | 8111 端口已被其他程序或另一个实例占用 | 关闭占用端口的程序，或修改 `[agent] port`（须不同于 `[server] port`），也可以设置 `enabled = false` |
| Agent 页显示“Agent 对话服务未连接” | 对话服务没有启动成功或已退出 | 查看启动窗口中的原因；处理后重新启动程序。其余功能不受影响 |
| Agent 页提示“还没有配置 AI 模型” | 三个来源都没有完整的模型配置 | 在“设置 → AI 模型”中填写并测试连接，见[接入模型](../model/) |
| 模型连接失败或超时 | 防火墙或代理阻止了平台访问模型服务 | 模型请求由平台进程发出，不由对话服务发出；在防火墙中放行平台的出站连接（Windows 上是程序目录 `.venv` 中的 `python.exe`）。对话服务只监听本机，**不需要**为它添加入站规则 |
| Windows 防火墙弹窗询问是否允许 `node.exe` 联网 | 首次启动对话服务时的系统提示 | 对话服务只在本机通信，可以不允许公用网络访问 |

更多问题见[常见问题](../../reference/faq/)。
