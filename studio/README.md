# Cable Studio

给电缆厂和科研人员用的专业软件，做两件事：**电缆型号**（导入结构表、算参数、按国标核对、改版、出规格书、建三维模型）和**载流量计算**（一款型号在地下直埋或排管敷设下的允许电流，哪根电缆先到温限）。有两种模式，操作同一份数据、走同一套宿主操作：**Agent 模式**是一个对话页，Agent 按技能调用软件的操作去做，结果以卡片呈现；**工作台模式**是专业界面（产品库、断面工作台）。方向、路线和界面规矩见 [ROADMAP.md](ROADMAP.md)。

## 运行

需要 Python 3.11+（安装 `backend/requirements.txt`，其中包含读取结构表的 `openpyxl` 和 `xlrd`）和 Node.js 22.19+；本次在 Python 3.11.8、Node.js 24.13.0 上验证。

```sh
cd studio
npm ci
npm run build     # 构建界面到 studio/dist
npm start         # http://127.0.0.1:8200/ ，只监听本机；首页是 Agent 模式，顶栏切到工作台
```

`npm run dev` 另起带热更新的界面（8201），接口转发到 8200 上的宿主。

| 环境变量 | 作用 |
| --- | --- |
| `CABLE_STUDIO_PORT` | 宿主端口，默认 8200 |
| `CABLE_STUDIO_HOME` | 工程目录，默认 `<仓库>/.data/studio` |
| `CABLE_STUDIO_PYTHON` | 计算核心与插件使用的 Python，默认 `python` |
| `DEEPSEEK_API_KEY` | Agent 用 DeepSeek（模型默认 `deepseek-flash`，可用 `CABLE_STUDIO_MODEL_ID` 改） |
| `CABLE_STUDIO_MODEL_BASE_URL`、`CABLE_STUDIO_MODEL_ID`、`CABLE_STUDIO_MODEL_API_KEY` | Agent 用任意 OpenAI 兼容接口 |
| `CABLE_STUDIO_MODEL_THINKING` | 思考强度 `off`（默认）/ `low` / `medium` / `high` |

密钥只从环境变量读取，不写入磁盘（会话文件、日志里都没有）。没有配置模型时 Agent 模式显示“模型未配置”，工作台照常可用。

## 结构

| 目录 | 内容 |
| --- | --- |
| `core/studio_core/` | Python 计算核心，不含算法：`runner.py` 按 `cablesim.run/2` 在独立进程里运行 `plugins/` 下的插件，运行前核对封签；`library.py` 型号库；`layouts.py` 敷设模板；`scene.py` 把型号、敷设、工况组成 `cablesim.domain/1` 文档；`study.py` 校核、扫描、选型；`methods.py` 方法卡与可信分档；`__main__.py` 给宿主用的本机服务（标准输入输出，每行一个 JSON） |
| `host/` | Node 宿主（TypeScript，由 Node 直接运行）：`store.ts` 工程文件夹；`operations.ts` 操作层；`products.ts` 产品库的操作；`agent.ts` Agent 服务（pi 会话层、写操作的审阅关口、对话落盘）；`agent-tools.ts` 把操作变成工具、只能读技能文件的 `read`；`chat-view.ts` 把会话文件还原成对话页要显示的消息；`report.ts` 计算书；`server.ts` HTTP 与界面 |
| `skills/` | Agent 的技能，每类工作一份 `skills/<名称>/SKILL.md`：载流量校核与选型、型号导入与标准核对、新建型号、按标准生成初始结构、型号改版、载流量表、GB 50217 校正、规格书与计算书、电缆三维结构建模 |
| `shared/` | 宿主与界面共用的类型、数值写法和绘图几何 |
| `ui/` | React 界面：`shell/` 外壳与两种模式的切换；`agent/` Agent 模式的对话页（assistant-ui 的原语加 kit 部件）、运行时和结果卡；`kit/` 设计会话定稿的部件（顶栏、外框、侧栏、对话、卡片、输入框、页头、数据表、标记、属性），`components/ui/` 基础控件；`types/` 型号库、型号工作区、导入和新建型号（`types/routes.tsx` 挂载这几条路由）；`rating/` 载流量计算工作台（`rating/routes.tsx` 挂载 `/workbench` 和 `/p/<工程>`）；`canvas/` 真实断面；`state/` 读取宿主与视图状态；`pages/gallery` 部件陈列（`/gallery`） |
| `core/tests/`、`tests/` | 真实流程测试与界面走查 |

计算核心直接引用仓库里的 `cablesim_sdk/` 和 `plugins/cablesim.iec60287/`，不复制、不改算法。厂家公开结构表读自 `backend/kernel/model_series_data/`。

## 界面

- 外壳：顶栏固定放品牌、模式切换（Agent、工作台）、模型名和主题按钮；`/` 是 Agent 模式（`/chat/<对话>` 打开一段对话），`/library`、`/workbench`、`/p/<工程>` 是工作台模式。切换时回到该模式上次停留的地方。
- Agent 模式（`ui/agent/`）：左侧对话列表（按今天、昨天、近 7 天、更早分组，可搜索），中间对话，底部输入框。页面只用 assistant-ui 的原语（滚动、输入框、起始任务、复制与重试、附件、会话列表）和 `ui/kit/` 的部件拼成，页面里没有自己的样式。输入框可以中止；任务进行中再发消息会在当前一步做完后插话；可把 Excel 或 CSV 结构表拖进去。空对话是两块（电缆型号、载流量计算），各带产品自己的一张图和库里现有的数量（系列、规格、工程），下面是起始任务（共六个），输入框下面有一块可以把结构表拖进去的区域。宿主连不上或模型没配置时，在输入框上方说明（连不上时有“重试”）；操作失败以右上角的提示条（sonner）说明。打开一段已有的对话时，最后一轮从那条提问起贴在页面顶部，上面不切掉任何东西；离开最新处时出现“回到最新”。回答正文按 Markdown 显示（表格、公式、代码）。对话里每个操作是一行（操作中文名、对象、状态，点开看要点，没有原始 JSON），写操作停在待审卡（每项改前、改后和单位，接受或拒绝），结果以卡片呈现：载流量结果卡（允许电流、先到温限的电缆、可信分档、断面缩略图；扫描和选型是表）、载流量表卡（一个规格在几种埋深和土壤热阻率下的允许电流）、标准提案卡（按标准生成的尺寸，每个数带条款和页码，以及还缺哪些）、GB 50217 校正卡（基准电流、各系数、校正后的值）、标准核对卡（通过、不通过、缺项的数量和不通过项清单）、文件卡（规格书、计算书的预览和下载）、三维模型卡（复用工作台的三维查看部件），每张卡带“在工作台打开”；同一段回答里去同一处的“在工作台打开”只留第一个，结果卡自带这个按钮时后面单独的那个不再出现（三维卡要等实体生成好才有按钮，不算）。卡片只拿引用，数字由界面向宿主读取，不经过模型。
- `design/tokens.css` 保存工程配色与字体，`ui/styles/theme.css` 映射为 Tailwind CSS 4 工具类，Tailwind 自带色板和阴影已关闭。界面长什么样以 `studio/DESIGN.md` 和陈列页 `/gallery` 为准。
- 型号库、型号工作区、导入和新建型号（`ui/types/`）只拼 `ui/kit` 与 `ui/components/ui` 的部件，不写自己的样式；`npm run lint:ui`（`npm run build` 先跑它）拦截颜色值、方括号尺寸、行内样式、原生控件和 Mantine，清单里的旧页面只减不增。型号工作区是断面（自有绘图 `canvas/cable-glyph`）、分层结构和四个页签（参数、标准核对、载流量表、版本与文件）；改结构、审核、规格书在对话框里做，审核只能由人点。图标用 `design/icons/`。
- 产品库、导入、新建型号、型号工作区和断面工作台按路由分别加载；首页不预加载型号工作区和三维绘图模块。
- 断面画布按真实比例绘制，不折断坐标。三层共用一个相机：GPU 层画土壤、网格、温度场和等温线（three 的 WebGPU 渲染器，没有 WebGPU 时用 WebGL 2）；SVG 层画电缆的真实结构层、尺寸和等温线数值；HTML 层放电缆标签和工具。标签逐个占位，后放的避开先放的。
- 温度场：方法只在一张粗的显示网格上发布温度场，并声明了它的模型（镜像线热源，取各电缆保存负荷下的总损耗）。显示层按这个模型逐像素计算，显示前先与方法发布的每个节点比较，差值超过 1e-6 K 就改为只用发布的节点线性插值。温度场只在保存负荷下显示。
- 工程数据只在宿主里。界面用 TanStack Query 读取，用事件流得知何时重读；界面自己的状态只有选中、工况切换、图层和相机。
- 其余：React 19.3 加 React Compiler（不手写记忆化）、TypeScript 7、Vite 8、Motion、TanStack Router（代码式路由）。

载流量计算的工作台（`ui/rating/`）覆盖：新建工程（从型号库选一款型号、选敷设方式、填工况）、查看“求什么、已知什么”并逐项修改、断面与温度场、结论（允许电流、先到温限的电缆、各部位温度、损耗、热阻、算法与可信度）、运行校核、扫描一个条件、按目标电流选截面、切换运行记录、导出计算书。运行是显式的：每次“运行校核”存一条不可改的记录，条件改过后记录标“已过期”，已知项上挂“已改”点；撤销和重做（Ctrl+Z、Ctrl+Y）作用于条件的修改。`/workbench?model=<型号库标识>` 带着型号进入新建工程（标识是型号库列表里的 `id`）；`/p/<工程>?run=<记录>` 按记录当时的条件和结果打开校核、扫描或选型。产品库的导入、修改、计算、审核与规格书流程见下节。

## 数据

一个工程是 `CABLE_STUDIO_HOME/projects/<id>/` 下的一个文件夹：

- `project.json`、`cable.json`（绑定的型号库版本）、`installation.json`、`conditions.json`、`method.json`：带结构版本号的输入，可改。
- `runs/<run>/record.json`：一次计算的完整记录（当时的输入、发给插件的请求、插件的结果与工件、各项摘要、插件版本、方法卡），写入后不可改。输入变了以后，旧记录仍在，只标为“旧输入”。
- `reports/<run>.html`：从运行记录生成的计算书，可打印，浏览器里可另存为 PDF。

## 产品库

入口为 `/library`（首页自动进入）。第一屏按资料来源组织系列，显示规格数及最新版本审核状态，可按型号、制造商、执行标准搜索，按来源与审核状态筛选。打开系列进入系列工作区（`/library/<系列>`），把一个系列当作一个工程对象来看，类似 CAD 里“零件 + 配置 + 设计表”：

- 左侧结构浏览器按由内到外列出当前规格的各部位，写出结构表的尺寸写法（导体直径、铜带厚度、钢带“层数×厚度”）和该部位标准要求的核对结论。
- 中间视图按保存的尺寸画出当前规格的实际比例断面，带部位编号气泡、外径尺寸线和比例尺，可缩放平移；“三维实体”切换到 CAD 插件生成的实体和 STEP 文件。底部步进器在相邻规格之间切换。
- 右侧属性面板显示当前选中的东西：规格概要（关键参数及来源、四类计算的状态）、一个部位（尺寸及来源、逐条标准要求和条款页码、材料）、一项计算（标准核对、电气参数、短路容量、载流量表，含条件与方法身份）、规格书或版本记录。修改结构在这里直接改数值，保存为新的草稿版本。
- 下方规格对比表一行一个规格，结构尺寸与计算结果并列，可排序、筛选、搜索、勾选和用方向键切换，Ctrl+C 把选中行复制成可粘贴到 Excel 的表格；底部给出各列范围。系列声明或标准规定的数值用不同颜色区分，修改过的数值带标记。

在任何一处选中规格或部位，其他三处同时跟随：选中绝缘，断面中只突出绝缘层，表中绝缘列高亮，右侧列出绝缘的尺寸和标准要求。计算、计算设置和审核在系列标题右侧，勾选规格后作用于选中项；批量计算进度显示在顶栏。原来的工程入口保留在 `/workbench`；最新规格可从属性面板进入断面工作台细算。

顶部“使用流程”按需解释导入、计算、审核和文件步骤；规格表上方的待计算、不通过、需补实测和拒算筛选按钮只在有对应规格时出现。标准核对中每个部位都能回到断面中查看；新草稿可在属性面板中单独计算。导入采用顶部五步进度，选择工作表后可查看其真实列名和示例值；声明按导体、绝缘、屏蔽、保护层和成品尺寸分组，显示原表已有值及待补依据。每一步的返回与继续操作位于表单底部，通过结构校验后才生成参数断面。

产品库保存在 `CABLE_STUDIO_HOME/library.sqlite`，按“系列 → 规格 → 版本”组织，宿主操作集中在 `host/products.ts`，与 Agent 共用。空库首次使用时迁入随软件提供的结构；这些结构保留公开资料或结构演示的来源身份，“已发布”只表示版本状态，不代表本厂确认了数据。

- 通过上传接口接收 Excel（`.xlsx`、`.xls`）或 CSV 结构表，读取工作表、表头和数据起始行，建议列对应关系；导入前由工程师确认。缺失尺寸由带依据的系列声明补充；缺 20 °C 电阻时查询 GB/T 3956—2008 表 2，查询不到就拒绝该行。列对应关系可以命名保存并复用。
- 预览逐行列出可用、缺项和告警。层厚放不进表列外径时拒绝该行；可疑的外径或重量只告警，不改原数。导入有失败行时必须明确选择跳过，才能只导入可用行。
- 每个版本保存结构、各值来源、外径闭合和推导依据。修改结构会生成新草稿，原版本和结果保留。审核按“草稿 → 待审核 → 已审核 → 已发布”逐步执行，记录人员、时间和意见；Agent 不能执行审核。
- 标准核对、电气参数、短路容量和载流量表在后台分批计算，通过事件流报告进度；相同版本和输入的结果直接复用。每份结果保存方法版本、输入摘要和计算条件；单个规格拒算不会替换成估计值，也不影响其他规格。
- “导入结构表”进入五步向导：文件、工作表、列对应、系列声明和预览。连续导入同一文件的多个工作表，或先试用带来源声明的人民电缆公开表；声明草稿在本机保留，重新打开后必须重新预览才能提交。
- 全系列与选中项均可计算，可选择计算类别、强制重算或在当前小批结束后停止。任务进度落盘，宿主重启会把中断任务明确标为失败，已经保存的结果仍可复用。计算完成、标准通过和人工审核分别展示。
- 批量审核（宿主操作 `library.review.batch`、`library.review.series`，界面暂时没有入口）要求填写意见并列出确切版本；存在缺项或问题时须明确确认。整个批次检查版本与前置状态，任一项不符则全批拒绝。修改结构要求原因并创建新草稿，原版本、原结果和原文件保留；修改字段单独标明工程师、时间、上版值与原因，保留原始依据。过期页面的修改会被拒绝，标称截面不能在尺寸修改中改掉。
- “版本与文件”生成真正的 PDF 规格书，包含结构示意、技术参数、载流量条件、标准条款及缺项、方法与数据来源。每份文件固定当时的版本、审核状态和结果，同时保存 JSON 来源快照及两个文件的 SHA-256；以后修改、审核和重算不会改写已生成文件。公开资料和参考计算始终标明身份，不作为本厂保证值。
- 文件页先展示当前版本的内容概览，生成后在弹窗中预览已保存 PDF。预览接口与下载接口返回相同字节，只改变 `Content-Disposition`；来源快照保持下载方式。浏览器不支持内嵌 PDF 时仍可直接下载。
- “CAD 实体”按当前保存版本调用封签的 `cablesim.cable-geometry` 插件，由 CadQuery / OpenCASCADE 构造实体，Three.js 只显示插件生成的网格。支持旋转、缩放、按部位查看及显示剖开；STEP 下载来自同一次建模，显示剖开不改变下载的实体。JSON 来源文件记录输入摘要、插件和方法版本、环境、工件摘要与近似声明。缺少单丝参数、波纹层等未覆盖构造会明确拒绝，不画替代模型。

CAD 需要给 `CABLE_STUDIO_PYTHON` 指定安装了 `plugins/cablesim.cable-geometry/src/requirements.txt` 的 Python 环境（`python -m pip install -r plugins/cablesim.cable-geometry/src/requirements.txt`，从仓库根目录执行）。模型是参数化工程几何：当前产品入口生成 180 mm 长的截面直线拉伸，紧压导体使用外径包络，不包含成缆扭转、接触形变与制造公差。几何有效不代表尺寸实测、材料保证或产品认证。

真实流程测试从人民电缆公开手册转录的工作簿导入表 1、2、3，共 35 个规格，保留原始资料摘要和系列声明；这不是企业自有结构表。对表 3 的三芯钢带铠装系列，10 个规格的直埋载流量可计算，`3×50` 的填充与内衬几何超出当前 IEC 方法适用范围（`SL_FILLER_GEOMETRY_RANGE`），载流量保持空值并报告失败。三芯排管表目前明确采用“三回水平”模板，不冒称单回排管。测试还核对批量与单算一致、缓存复用、减薄绝缘触发 GB/T 12706.2—2020 表 7（PDF 第 15 页），以及审核留痕。

Windows 核心进程在开始读取标准输入前加载工作簿依赖，避免工作线程初始化 C 扩展时与管道读取互相等待；后续增加 PDF 等依赖时沿用启动阶段加载的约定。关闭宿主会等待核心进程退出，再关闭产品库和释放文件。

### 型号能力（后端）

下面四项都是 `host/` 里新文件中的操作（`type-operations.ts` 统一注册），各带 `tool` 名和中文说明，Agent 自动可用；写下的东西都留来源、人和时间。

- **从零新建**：`library.series.create`（`create_series`）新建空系列，声明同导入时的“系列声明”；外径填写的精度要说明（`outer_diameter_precision_mm`，或在计算用参数里给 `diameter_rounding`，或采用参考参数），软件不替你选。`library.spec.create`（`create_spec`）在系列里按层填写一个规格，字段、单位、尺寸校验和外径闭合与导入完全一样（同系列已有的规格一起参与构建，重量比小一档还轻这类离群提示照常给），建成第 1 版草稿，和导入的草稿是同一种东西。来源记为“人工填写”（Agent 填的记为“Agent 填写（待工程师核对）”），填写人和时间在版本、事件日志和规格书里，规格书的“资料”写这次填写而不是系列导入时的文件；改结构生成新版本后仍是手填的，每个数的依据随数值或随修改记录保存。未给的尺寸取系列声明，缺了就拒绝，字段拼错、计算用参数拼错也拒绝。两个写操作带审阅说明（`review`：不写库、走同一个构造器），Agent 提出时先交给工程师。
- **载流量表写回规格书**：`library.rating.table`（`build_rating_table`）按写明的敷设条件逐条算允许电流，存成这个规格版本的一张表，`library.rating.tables` 读取。批量计算里的 `rating` 仍是固定的基准表（0.7 m、25 °C、六种土壤），这里补的是自定条件；每个条件在一个专用工程里做一次 `run.rate`，所以表里每个数是一条运行记录（工程加记录标识，记录里有输入、插件和方法版本），也等于用同样输入单独校核的结果。规格书 PDF 带这张表，审核之后追加的表会标明审核不覆盖它；方法不覆盖的条件在表里写拒算原因，不补估计值；带回填或包封区域的敷设暂不能写进表（表里还没有它们的尺寸和热阻率）。中途失败的表不保存，专用工程标为“未完成”，版本事件里留一条记录。
- **按标准生成初始结构**：`structure.propose`（`propose_structure`）运行 `cablesim.standard-check` 的 `structure-proposal`：给执行标准、电压等级、芯数、导体材料与截面、绝缘材料（目前只有 XLPE）、铠装形式，返回每个尺寸及其标准号、表或条款、印刷页和 PDF 页，并把提案原样保存、给出提案标识（`get_proposal` 读取）；默认只给绝缘厚度，工程师给出屏蔽层厚度后连内衬、铠装、外护套（GB/T 12706 附录 A/B）一起算。`missing` 列出还要工程师补的尺寸（导体外径、成品外径等）。`create_spec` 引用提案标识时，提案里的数不能改、依据取自提案，提案标识、标准和方法版本随版本保存；不引用时依据是自己写的文字。执行标准与电压对不上、表外电压和截面都拒绝，不给近似值。标准核对对内衬、钢带、外护套三项目前只在“来自完整提案的草稿”上判定，库里建出的规格这三项为未覆盖（不是不通过）。
- **GB 50217 校正**：`correction.gb50217`（`correct_ampacity_gb50217`）把工程里一条基准运行记录（单回路、环境 25 °C）的允许电流，按工程当前的环境温度和并列敷设校正，给出各系数（条款、页码）和校正后的值，存为不可改的校正记录（`correction.list`、`correction.get` 读取）；方法卡在 `methods.list` 里，分档“参考”（只有插件自带的手算核对，没有整链公开算例）。适用范围：三芯电缆、直埋、10 kV 及以下，表外条件拒绝不插值。基准与当前须同埋深、同土壤热阻率、同系统电压、同频率、同护套接地方式，同款型号、单回路、环境 25 °C，这些软件逐项核对并列出；基准条件是否成立由工程师确认，确认的人记在校正记录里，不确认时只返回核对项、不给数，Agent 不能代为确认。

## 操作层与 Agent

工作台的每个动作在 `host/operations.ts` 和 `host/products.ts` 里只有一份：人点按钮经 `POST /api/ops/<操作>` 调用，Agent 把同一个操作当工具调用。

Agent 的内核是 pi 的会话层（`@earendil-works/pi-coding-agent` 的 `createAgentSession`，`host/agent.ts`），它自带的读写文件、命令行和联网工具全部关闭：

- **工具**：所有带 `tool` 名的操作，由 `host/agent-tools.ts` 逐个转成工具，调用一个接一个执行；外加一个叫 `read` 的工具，只能打开技能文件，别的路径（包括仓库里的 `AGENTS.md`、`CLAUDE.md`）一律拒绝。工作台自己的草算（`draft.*`）不是工具，Agent 用 `run_rating`。
- **只许人做的**：审核、批准、发布（`library.review*`）带 `human_only` 标记。`Studio.invoke` 对 `by: 'agent'` 的调用在校验参数之前就拒绝（403），它们也不在工具里。
- **审阅**：写操作（新建、重命名工程，更换型号，改敷设、工况、方法参数，导入系列，改结构）在 `tool_call` 钩子里停住，界面出现待审卡；接受后才执行，拒绝的原因会告诉模型。每个写操作都要有审阅说明（`plan` 或 `review`），宿主启动时检查，没有的不会作为工具提供。审阅说明在上卡之前就把操作会拒绝的情形拒掉（系列已存在、导入没有可用的行、改结构的值没变或版本不对等），不让人去批准一件做不成的事；说明里没有任何变化的改动不上卡；接受之后宿主再核对一次卡上写的东西还在不在：工程的名称或输入在等待期间被人改过（保存一条运行记录不算改动），或者所选型号在库里有了新版本，已经接受的改动就不执行，步骤标为失败并写明原因，卡上同样显示“已接受，但没有执行”；改结构则固定在卡上那一版，版本变了同样拒绝。导入卡上的来源写的是实际会存进每个规格的出处，不只是上传的文件名；依据文字不截断。停止对话时等待中的改动按拒绝处理，停止发生在审阅说明还在计算的时候也一样，不会留下无人应答的卡。
- **计算和导出**（校核、扫描、选型、批量核对、规格书、计算书、三维实体）直接执行，生成运行记录或文件，不改输入。`compute_series` 对 Agent 会等这一批算完才返回。
- **技能**：`skills/<名称>/SKILL.md`，中文，写清什么时候用、步骤、用哪些工具、容易错在哪、什么情况必须停下来问人。系统提示里只有技能的名称和一句说明，模型要用时用 `read` 取全文。
- **系统提示**：电缆工程师同事；数字只来自工具结果；缺数据如实说；改动先交人审；回答第一句是结论，其余各写一件要注意或要决定的事（至多三句），一共不超过四句话，每句不超过 50 字、各占一行，尺寸、表和出处留给卡片，不写内部编号，不写工具没给的百分比和差值。运行结果里的电缆用能直接对工程师说的名称，不给模型计算内部的编号（模型会照抄）。发给模型之前（`before_agent_start`）去掉 pi 默认带的“当前工作目录”一段，技能只写名称不写文件位置，模型不知道本机的任何路径；工具结果、工具错误和审阅失败的原因里，本机已知的目录（工作目录、仓库、主目录、临时目录，连同后面跟着的路径）和盘符路径、网络共享、系统目录一律替换成“〈本机路径〉”（`scrubPaths`；网址里的 `/home/` 之类不算）。测试对模型实际收到的请求断言这些。Agent 的守卫类测试（审阅与执行一致、停止、拒绝、路径过滤、只许人做的操作、工程状态和型号版本的核对、导入来源、结果里的电缆名称）都做过破坏性验证：临时破坏被测代码，确认对应测试变红，再还原；其余测试没有做这一步。计算返回的消息里的电缆、回路编号也换成名称，说不出名称的换成“某根电缆”。
- **会话**：落在 `<CABLE_STUDIO_HOME>/agent/sessions/`（pi 的会话文件，每行一个条目），宿主重启后列表和历史还在；审阅结果存成会话里的自定义条目。对话页看到的消息由 `host/chat-view.ts` 从会话文件还原，所以正在进行的对话和重新打开的对话长得一样；重启时没做完的步骤显示“已中断”。
- **结果卡**：操作可以带 `card`（引用，如运行记录、系列、文件、规格版本，加工作台深链接）和 `notes`（步骤行里的要点）。引用和要点存在会话里，卡片里的数字由界面向宿主读取。待审卡在要人决定时展开，决定之后折成标题和结果一行（可点“看改动”再展开），一段对话里有很多次决定时不会变成一面表格墙；“回到最新”按钮在页面够宽时放在输入框旁边的空白处，不压在文字上。
- **网络**：pi 的安装遥测和模型目录下载都关了（`PI_TELEMETRY=0`、`PI_OFFLINE=1`，设置里 `enableInstallTelemetry: false`），密钥用内存凭据，不写 pi 的 `auth.json`；唯一的外部流量是配置好的模型接口。

### 内核试验结论（第 1 轮）

先用脚本化模型试验能否从 `pi-agent-core` 的裸循环换到会话层，三项都通过才换，结论：换。

1. 内置工具全关、只注册我们的操作时，写操作能停下来等人接受或拒绝，然后继续：用内联扩展的 `tool_call` 钩子，钩子里等一个 Promise。拒绝时工具不执行，原因交给模型。注意：等待审阅时必须监听 `ctx.signal`，否则 `abort()` 会一直等到有人答复；所有工具要设 `executionMode: 'sequential'`，否则同一轮里的 `[改动, 校核]` 会并行，校核按改动前的输入算。
2. 技能能被发现并按需加载：pi 自己的加载器能找到 `SKILL.md`，但它只在选中了 `read` 或 `bash` 时才把技能目录写进系统提示。所以注册一个名叫 `read`、只能读技能文件的工具顶替内置的，技能目录就由 pi 原生写进提示，模型用它取全文；读别的文件被拒绝。
3. 仓库的开发约定不进上下文：默认的发现会把往上各级的 `AGENTS.md`、`CLAUDE.md` 读进提示（对照试验证实），所以用 `noContextFiles`、`noSkills`、`noExtensions`、`noPromptTemplates`、`noThemes` 关掉发现，再显式给出技能目录和系统提示。

另外试了：会话落盘后关闭、重开、再发消息；留在文件里的“有调用没结果”的条目，pi-ai 在发给模型前会补上占位结果，不会让模型接口报错；发消息时 `steer` 能在等待审阅期间排队，等这一步做完再送给模型；整个包第一次加载约 5 秒、多占 75 MB，所以宿主启动时后台预加载，不拖慢启动。

## 可信分档

每条结果带分档和方法卡（方法、适用范围、假设、验证依据）。分档由实际计算的敷设形式决定，与结果数值无关，规则在 `core/studio_core/methods.py`：

- **可交付**：单回路、单芯、光滑金属套，直埋或穿管。依据是 CIGRE TB 880 算例 0-1（接触品字形直埋）、0-2（接触品字形穿管）、0-3（平排穿管加包封）的整链对照。直埋水平和留间隔品字形没有单独的整链公开算例，方法卡里写明了这一点。
- **参考**：多回路、矩形回填与包封、三芯、皱纹金属套、外部给定损耗系数。只有手算或解析自洽检查。
- **探索**：留给尚未通过评测基准的方法，目前没有方法落在这一档。

分档说的是方法；型号数据的来源另外标注。库里的型号是“结构演示”或“公开厂家资料”，都不是厂家确认的产品数据，计算书的结论处会写明。

## 参数覆盖与核实

下表是技术参数表里每一类数现在的来路，以及用公开厂家手册核实的结果。对照源是 Bahra 的中压铅套电缆手册（CU/XLPE/LC/PVC 3.6/6 kV 单芯，13 个截面，`core/studio_core/catalogues/bahra_mv_lead_sheathed.json`，写明了页码和文件摘要）。

| 参数 | 来路 | 与手册对照（13 个截面） | 说明 |
| --- | --- | --- | --- |
| 20 °C 直流电阻上限 | 标准表（`cablesim.standards-basis`、`cablesim.standard-check`） | 与手册一致 | 手册用的也是标准上限 |
| 90 °C 交流电阻 | `cablesim.type-electrical` | 平均差 0.39 %，最大 1.31 % | 另有 TB 880 中间量对照到 1e-6 |
| 电容 | `cablesim.type-electrical` | 偏高 5–10 % | 手册没给介电常数；这里取 IEC 标准参考值 2.5，手册约按 2.3 |
| 电感（导体几何项） | `cablesim.type-electrical` | 差 0–5 % | 手册外径取整到毫米 |
| 导体 1 s 短路电流 | `cablesim.type-electrical`（IEC 60949） | 平均差 0.05 %，最大 0.08 % | 90 → 250 °C |
| 金属套 1 s 短路电流 | 同上 | 平均差 2.4 %，最大 5.3 % | 手册没给温度，按 80 → 170 °C；手册只有两位有效数字 |
| 直埋载流量，品字形，两端接地 | `cablesim.iec60287` | 平均差 3.9 %，最大 9.8 %（25 mm²）；95 mm² 以上在 4 % 内 | 方法本身另有 TB 880 精确对照 |
| 直埋载流量，水平、间隔一个外径 | `cablesim.iec60287` | 平均差 3.5 %，最大 8.7 % | 手册没给间距 |
| 直埋载流量，水平紧贴 | 无 | 方法拒算 | 镜像法要求热源不接触 |
| 单点接地的载流量 | `cablesim.iec60287` | 默认参数下拒算 | 必须计入护套涡流损耗，默认是“不计” |
| 空气中、桥架、电缆沟、隧道的载流量 | 无 | 算不了 | 先用厂家基准值加国标校正，或人工填写 |
| 电压降 | 无 | 算不了 | 有交流电阻和电抗后是一个简单公式，要做成插件能力 |
| 每公里重量、用料 | `cablesim.cable-geometry` | 未核实 | 已接入 CAD 实体与 STEP；密度或绞入参数不足时质量仍为空，界面不将几何体积当作产品保证重量 |
| 最小弯曲半径、试验电压等规定值 | 标准或厂家规定 | 未核实 | 逐项查 `cablesim.standards-basis`，没有的人工填写 |

对照中发现、产品库必须解决的事：

- 短路容量和电气参数要求材料写明标准材料类别（铜、铅、XLPE 等），并要求由标准依据插件发出的依据快照；缺少类别或依据的部件不给结果，不能从型号猜材料标准类别。
- 厂家手册不给半导电层厚度和介电常数，企业自己的结构表导入时要带这些列。
- 单点接地时要自动改为计入涡流损耗，否则方法拒算。

`core/tests/test_catalogue_agreement.py` 把载流量对照固定成测试；`core/tests/test_product_methods.py` 对照电气参数和短路容量，并检查材料未声明时没有结果。

## 测试

```sh
python -m pytest studio/core/tests          # 计算核心；设 CABLESIM_TB880_FIXTURES 后重算 TB 880 六个算例
cd studio && npm test                       # 宿主：工程师流程、产品库流程、Agent 流程（脚本模型：工具集与请求内容、仓库约定文件不进上下文、读技能、审核操作拒绝 Agent、导入与改结构的审阅、拒绝带原因、停止（含审阅说明计算中停止）、审阅期间工程或规格版本被改、导入里只许人定的参数不被带出、空改动、路径过滤、结果里电缆用名称、型号的九个操作（工具集、新建须审阅、载流量表和标准提案和校正的卡片、校正的确认只许人做）、插话、重启）
cd studio && npm run build && npm run walk  # 真实导入、批量计算、审核、修改、PDF 与工作台；载流量工作台、型号库和 Agent 模式（1366×768 和 1920×1080）
cd studio && npm run build && npm run walk:agent  # 只走 Agent 模式，约 1 分钟
```

Agent 模式的走查（`tests/agent-walk.ts`）用脚本化的模型，在页面里像人一样操作：点起始任务、审阅并接受新建工程、读载流量结果卡、从卡片进工作台再回到对话、看标准核对卡和规格书文件卡（预览、关闭）、拖一张 CSV 结构表进输入框并发送、接受了一项后工程被人改过的卡片（显示“已接受，但没有执行”）、三维结构卡的两种看法；每步截图并检查文字有没有重叠或被截断，在 1366×768 和 1920×1080 各走一遍。

走查的截图默认写到 `<仓库>/.tmp/studio-walk/`，也可以把输出目录作为参数给出。产品库走查在隔离库中经页面导入 35 个规格，计算三个系列，检查实际参数、人工审核步骤、新草稿、减薄绝缘的三项不通过及旧版本保留；同目录留下真实下载的两份 PDF、JSON 快照和公开 Excel 样例。截图与布局检查覆盖 1366×768 和 1920×1080。测试内的审核意见明确标为隔离验收，不改用户工程库。

安装 CAD 环境后，`core/tests/test_product_geometry.py` 通过真实插件导出 STEP，再由 CadQuery 回读，验证实体有效性、体积及外径/长度，并验证缺参数和未覆盖构造确实拒绝。设置 `CABLE_STUDIO_VERIFY_CAD=1` 的界面走查还会在页面生成 CAD、下载 STEP 和来源 JSON，核对下载字节与插件结果一致。

`core/tests` 核对的内容：TB 880 算例 0-1、0-2 及其变体经“型号库条目 → 组装 → 独立进程运行”重算出公开值；独立进程的结果与进程内直接调用算法逐位相同；公开的起帆结构重算出 CableSimPro 发布时记录的值；扫描、选型、拒算、封签被改时拒绝运行、本机服务往返。
