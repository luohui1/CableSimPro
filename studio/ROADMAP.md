# Cable Studio 方向与路线

Cable Studio 做什么、先做什么、怎样算做完，以本文件为准。运行方法和能力边界见 [README.md](README.md)。方向有变就改这里，不另起文件。

## 产品

给电缆厂和科研人员用的专业软件。做两件事，有两种用法。

### 两件事

| 事 | 工程师要干成的 | 交出的东西 |
| --- | --- | --- |
| 电缆型号 | 把一款电缆定下来：各层结构、电气参数、按国标逐项核对，存进型号库并留版本 | 规格书 |
| 载流量计算 | 回答一款型号在某种敷设和环境下能带多大电流、哪里先到温限 | 计算书 |

两件事相连：载流量计算用的电缆取自型号库；算出的载流量表回到型号的规格书。

### 两种模式

两种模式操作同一份数据，走同一套操作。

| 模式 | 是什么 |
| --- | --- |
| Agent 模式 | 一个对话页。把事情交给 Agent，它按技能调用软件里的操作去做。过程和结果以卡片呈现（断面、结果表、待审改动、文件），每张卡都能转到工作台里看 |
| 工作台模式 | 专业界面，工程师自己动手：型号库、一款型号的工作区、载流量计算的断面工作台 |

### Agent

- 内核用 pi。
- 能力用技能包装：每类工作一份 `studio/skills/<名称>/SKILL.md`，写清什么时候用、按什么步骤做、容易错在哪。
- 工具就是软件的操作层。人点按钮和 Agent 调工具走同一套操作，所以工作台里能做的事 Agent 都能做，审核、批准、签发除外。
- 写操作先交人审，接受后才生效。
- 建模（电缆三维结构）已有插件，交给 Agent 用。有限元仿真依赖超算，接通后作为技能加入；本机不跑求解器。

不在范围内：询价单、招标文件响应这类业务流程。

## 底线

1. 宿主不内置算法，计算全部由封签插件完成。
2. 缺数据就明确拒算，不编数。
3. 每个数都能追到输入、方法和版本；没有对照算例的方法不标“可交付”。
4. Agent 只提方案。数值只来自计算结果，不来自模型。

## 保留什么，重做什么

- 保留：`studio/core/`、`studio/host/` 的操作层和产品库、现有测试，以及根目录的 `plugins/` 和 `cablesim_sdk/`。它们验证过，重写只会带来错数的风险。
- 重做：`studio/ui/` 整层，按两种模式重做；Agent 内核按上一节升级。
- 断面画布、电缆结构图这类领域图形是自有绘图，继续用。

## 组件

1. 通用控件一律用成熟的开源组件，不手写。先找现成的；没有现成的，用成熟的无样式原语拼；不从零造。
2. 全站一套底座，第 1 轮定下后不再换。默认方案：Tailwind 4 加 shadcn/ui 做通用控件，assistant-ui 做对话；表格、分栏、图表、命令面板各选一个成熟库。安装前核对版本、许可证和与 React 19 的兼容性。确有硬伤才换，换了记在这里。
3. 现有的 Mantine 页面在工作台模式重做时一并移除，不长期并存两套控件。
4. 视觉只认 `design/tokens.css`。
5. 每加一个库，写明它负责什么；用不上的当轮删掉。

## 界面规矩

1. 动手前写一句“这屏要干成哪件事”。写不出来，就不做这一屏。
2. 一屏只有一个主按钮，指向下一步。
3. 面板贴边平铺，用细线分隔，不用卡片套卡片；面积留给表格和图。
4. 次要信息（哈希、路径、标准原文）收进点开才看的来源说明。用户页面不出现原始 JSON。
5. 正文不小于 13px；不用成行的灰色小字堆说明；任何宽度下文字不重叠、不截断。
6. Agent 模式：回答里的数只来自工具结果；结果用卡片呈现，不写成大段文字；文字交代不超过五行。
7. 草算和已存档的结果、未审和已审的型号，在界面和导出文件上都要分得清。

## 路线

每一轮结束都要能打开来用。

### 第 0 轮：收拢

- 未提交的改动存档成提交；主检出里未提交的文件在仓库外留一份副本。
- 根 `AGENTS.md` 的开头改为指向 `studio/` 和本文件。
- 旧平台（`backend/`、`frontend/`）不再接新功能，暂不删除。

### 第 1 轮：Agent 模式跑通

- 定下组件底座；做新外壳，带模式切换。
- 内核：先做小试验，决定是否换成 pi 的完整会话层。三项都通过才换：只保留自有工具时写操作仍能停下来等人审；技能文件能被加载；仓库的开发约定不会进入 Agent 的上下文。不通过就留在现有内核上，用“技能目录加按需读取”实现同样的效果。
- 技能、全部操作成为工具（审核类在代码里拒绝 Agent）、会话落盘、接通真实模型。
- 对话页：会话列表、流式消息、工具步骤、结果卡、待审卡、输入框（可中止、可插话、可拖入结构表）。
- 完成标准：在对话页里交办三件事并做成，用真实模型各跑通一遍。
  1. 导入一份结构表，算参数并按国标核对，列出不通过的项。
  2. 算一条线路的载流量，说明哪根电缆先到温限。
  3. 导出一份规格书或计算书。

### 第 2 轮：工作台模式重做

- 载流量计算：断面工作台搬到新外壳和新底座上，一眼看得出在求什么、已知什么、结论是什么。
- 电缆型号：型号库，加一款型号的工作区（结构断面和分层表、参数、标准核对、版本、规格书）；新建型号可以从零填，也可以按标准生成初始结构。
- 两种模式互通：工作台里选中的对象可以交给 Agent；Agent 的结果可以在工作台打开。
- 旧页面和 Mantine 删除。
- 完成标准：两件事各自从头做到交出文件，人在工作台走通一遍，Agent 在对话页走通一遍。

### 第 3 轮：做深

每项都要有对照算例。

- 载流量：GB 50217 校正；空气中敷设（含日照）；多回路、排管组、三芯分支的独立复算；应急和周期负荷。
- 型号：结构图 DXF 和三维 STEP 导出；厂家资料导入核对。
- Agent：草稿层和整单审阅（连续改动先落草稿，基于草稿试算，最后一次审完）；模型在设置页可选。

### 后续方法（不排期）

进入条件：两种模式已可用；有公开算例可对照；一次只进一项。

- 护套感应电压与交叉互联（候选引擎 OpenDSS）
- 线路压降、充电电流、系统短路（单回压降先用已有电气参数直接算；系统级候选 pandapower）
- 敷设牵引力与侧压力
- 经济截面
- 有限元复核与互热修正模型（依赖超算）
- 厂家型录解析（候选 Docling，装之前先评估体积和内存占用）

## 验收

1. 数：测试对照公开算例；新增方法先有算例，再进界面。
2. 用：每轮结束，把关的会话在 1366 和 1920 两种宽度下把完成标准里的事实际做一遍，对照上面的规矩检查。用户随时可以打开看，提出的问题排在最前面改。

测试通过不等于界面通过。

## 工作方式

- 同一时间只有一个会话改 `studio/`。在工作分支上提交，不合并 `main`，不强推。
- 每轮顺序：动手前请顾问复核方案，实现，独立审查，把关会话上手验收。
- 仓库是公开的：推送前检查密钥，存档用的分支不推送。模型密钥只从环境变量读取，不写进任何文件。
- 每轮结束跑 `npm test` 和 `npm run walk`；改了 Python 跑 `python -m pytest`；改了插件按根 `AGENTS.md` 检查封签。
