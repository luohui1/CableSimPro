# 规格书与计算书

## 计算书

1. 用 `object_find` 定位工程和研究，`run_list` 找保存运行，`run_read` 核对成功状态、完整性、当前性、方法版本及来源。没有运行不能导出，不把输入参数当结果。
2. 明确交付引用哪些运行；过期或失败结果要如实说明，不能默默重算。
3. 用 `propose_delivery(run_ids)` 提出生成计算书，待人接受。接受只授权卡上列出的运行与文件；结果回执失败时说明原因，不能伪造下载链接。
4. 使用返回的文件卡/老平台交付入口。正文称研究名称及“计算书”，不复述交付标识、下载路径或 UUID；这些留在可追溯记录中。文件数字来自保存证据，导出不重新求解。

## 规格书

1. 用 `type_read` 的结构、运行和规格书视图读取准确型号修订、要求、来源、核对结果及缺项；先查已有文件，避免重复生成。
2. 明确用途：`audience` 为内部草稿或客户交付。内部稿按实际状态标示缺项，客户稿缺必要证据时必须拒绝，不降级后声称可交付。
3. 需要补核对时按 `cable-revision` 逐项提出研究和运行，分别等待人接受。不要让一个“导出”暗中创建研究或重新计算。
4. 用 `propose_type_specification(audience)` 提出导出，等待人接受。展示真实返回的规格书记录与工作台入口，说明草稿/审核状态及追溯范围。

接受提案不等于审核产品质量、批准工程结果或发布型号。用户拒绝后停止对应动作；版本变化导致原批准失效时重新读取并重新提案。
