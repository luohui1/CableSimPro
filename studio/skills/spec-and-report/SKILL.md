# 规格书与计算书

## 计算书

1. 用 `object_find` 定位工程和研究，`run_list` 找保存运行，`run_read` 核对成功状态、完整性、当前性、方法版本及来源。没有运行不能导出，不把输入参数当结果。
2. 每份计算书引用一条完整保存运行。过期或失败结果要如实说明，不能默默重算。用户要多条时分别提出文件，不把多条拼成未经审阅的计算书。
3. 从用户已提供的信息取得 `document.organization`（单位）、`document.number`（文件编号）、`document.revision`（版次）；可选 `header`、`footer`、`issued_on`。缺少必填项就明确询问，不把工程名冒充单位、不编造编号、日期或签名；同一会话已明确提供的字段不用再问。
4. 用 `propose_delivery(run_ids, document)` 提出正式计算书预览，待人接受。待审卡列出单位、文件编号、版次和保存来源；接受只授权这一版文件，来源或签核变化则拒绝并重新提出。
5. 接受后使用返回的 PDF 文件卡及来源研究入口。文件由正式交付 `/api/formal-deliveries/preview`、`/export` 的同一服务生成，带四个签栏、追溯页和完整来源快照；导出不重新求解。正文称研究名称及“计算书”，不复述下载路径、UUID 或内部摘要。回执失败时说明原因，不伪造下载链接。

## 规格书

1. 用 `type_read` 的结构、运行和规格书视图读取准确型号修订、要求、来源、核对结果及缺项；先查已有文件，避免重复生成。
2. 明确用途：`audience` 为内部审阅或客户交付；用户没说时先问，不替用户选择。正式文件两种用途都须已有结构、电气、载流量、短路、标准五个通道的保存运行；缺通道时列出缺项，不降级为旧版文件后声称已正式交付。
   - 内部审阅稿：五个通道都有保存运行即可提出预览；通道里的缺项、未覆盖和阻断项随文如实列出，它们不是内部稿的导出障碍。内部稿保留真实草稿状态。
   - 客户交付稿：工具还会检查各通道证据完整性。缺项或未覆盖的条目须补齐输入并重新运行，或由人在型号工作台“审核与发布”中逐项声明本次发布不含该项（你不能代为声明）。
   - 能否导出以 `propose_type_specification` 的核验为准：不要只凭阅读核对结果自行断定“出不了”。工具拒绝时转述它列出的缺通道或缺证据，再说明上述补齐或声明的路径。
3. 需要补核对时按 `cable-revision` 逐项提出研究和运行，分别等待人接受。可复用准确保存的研究配置；结构改变后，载流量表须用原已声明工况重新编译，不能继续引用旧型号修订。不要让一个“导出”暗中创建研究或重新计算。
4. 按计算书第 3 步取得明确文件元数据，用 `propose_type_specification(audience, document)` 提出正式规格书预览，等待人接受。展示真实 PDF 文件卡与型号工作台入口，说明草稿/审核状态及追溯范围。

接受提案不等于审核产品质量、批准工程结果或发布型号。设计、校核、审核、批准签栏只引用真实已有记录；没有记录就留空。用户拒绝后停止对应动作；版本变化导致原预览失效时重新读取并重新提案。已成功导出的回执和文件可重读，断线恢复不能重复生成。
