# 载流量研究

## 读取结论

1. 用 `object_find` 按准确名称查研究，取名片的所属工程；有歧义时列名称请人选，不能猜标识。用 `study_list`、`study_read` 核对保存定义与条件。
2. 用 `project_digest` 或 `run_list` 找保存运行，再用 `run_read` 读取关键量值、显示单位、限制对象、方法版本、来源、适用范围和当前性。默认用工具摘要说明结论；需要核对具体量值时才按分页参数读取该项，不能为了有省略项就把全部明细灌入上下文，未读明细不能称已逐项核对。
3. 让界面展示结果卡和工作台入口。回答先给允许电流及口径，再给限制、数据来源和当前性；负荷电流不能当允许电流，历史结果不能说成当前结果。

## 新建、重算和对比

1. 先用 `workspace_read` 读取真实工程输入。确认电缆版本、敷设、埋深、土壤热阻率、环境温度、负荷以及方法所需数据；缺项说明字段和工作台补录位置。不要套用演示值、契约默认值或常见值。
2. 优先从 `study_read` 得到可复用的已保存研究；也可用 `method_list` 和 `plugin_inspect` 读真实方法及参数契约。调用 `propose_study`，待人接受后才取得新研究标识。
3. 条件与请求不一致时，只用 `workspace_read` 给的稳定路径和显示单位调用 `propose_domain_changes`；方法参数用 `propose_method_parameters`。每项等人接受，重新读取保存版本后继续。
4. 用 `propose_study_run` 提出运行。接受后的回执必须有成功的真实运行，才可用 `run_read` 解释结论。预检失败、方法不支持或缺数据时停止，不换条件凑结果。
5. 改条件前保留原运行引用供工具调用。新运行成功后用 `study_compare` 比较两个保存结果；只使用比较工具实际提供的差值、口径和显示单位。正文使用研究名称与记录序号，不写内部运行标识或字段路径；完整差异在卡片与保存记录里查看。
6. 需要计算书时按 `spec-and-report` 调用 `propose_delivery`，仍等待人接受。

## 边界

- 模型只能提出业务写入提案；新建、修改、计算和生成文件都不得跳过批准。拒绝后停止相应后续动作，不换工具重试同一写入。
- 会话修订冲突时重新读对象、重新提案；不能把旧批准用于新输入。
- 扫描、选型和原生仿真仅在桥的工具与方法实际支持时执行；没有工具就给出工作台入口和缺能力说明。原生求解只能按宿主指定的超算途径。
- 不自行计算未返回的百分比、温度、损耗或核对结论。方法显示名称和版本，内部标识只用于工具调用。
