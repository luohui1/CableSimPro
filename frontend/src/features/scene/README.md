# 场景与热分析工作区

正式入口：研究的「敷设截面 → 三维」；载流量、温度场、暂态温度、电热耦合模块的「可视化」页签。读取现有工程预览及保存运行，不建立第二份工程，不修改计算插件、原始数据或审批路径。原 AppShell、主导航、研究操作栏及共有样式保持不变。

## 场景查看与精确几何

敷设场景在对象列表旁提供「场景视图」和「几何工具」。前者使用原生 WebGL 2，读取同源显示网格，提供实例复用、GGX 材质光照、选中高亮、旋转/平移/缩放、相机预设、显示剖切和环境透视。后者保留 OCCT 及原有几何工具。两者共享工程对象选择，不能把显示三角形或 shader 剖切当作精确 CAD 拓扑。没有引入 Three.js 或新的运行时依赖。

鼠标拖动旋转，Shift/右键拖动平移，滚轮缩放；触控双指缩放。方向键旋转，F 适应窗口，1/2/3 切换轴测/端面/俯视。视图按需绘制；后台停止绘制，卸载释放事件和 GPU 缓冲区。显卡上下文丢失时明确报错，重试使用新画布。配色来自 design/tokens.css；材质参数仅控制外观。

分组对象列表支持搜索、选择、显示/隐藏、隔离与恢复。控制只影响显示，Blender 导出仍包含完整原场景。显示预算为 128 对象、512 绘制组、50 万唯一顶点、100 万唯一三角形、8192 实例与 400 万展开三角形；超限明确失败，不静默丢对象。像素比上限 2，单边 framebuffer 上限 4096。这些是显示资源限制，不是求解器能力声明。

## 场景构件方案

在原三维视图里展开「场景构件设计」，选择直埋剖面、回填区、排管组、电缆沟、圆形隧道或梯式桥架。净宽、净高、构件厚度、间隙及支撑间距均以米填写；「填入建议尺寸」只填写尚未应用的展示建议，点击「预览构件」才生效。首次进入仍是原工程场景。

构件包含剖视土体、回填条、带真实内孔的保护管开窗、沟壁和底板、分段盖板、隧道衬砌和检修走道，以及桥架纵梁、横档与支座。圆环内孔不填成实心，平面保留独立法线，重复构件共享网格实例。半径、壁厚、净空、管间干涉和重复数会检查；不能容纳原电缆时拒绝，不自动改变电缆位置。圆形隧道要求净宽等于净高，不偷偷替换为其他断面。

这些是 **展示构件方案**，不是已经批准并参与求解的工程实体。身份使用独立的 presentation 前缀与原输入身份关联；原电缆、原场景和矩阵不被修改。预览时只在当前视口隐藏原环境，原对象数据仍保留；「恢复原工程场景」撤去展示方案。无效参数撤去之前的方案并报错，不把旧方案冒充新输入。整页刷新不保存这些查看偏好。

现有 Blender 按钮仍导出原工程场景，不包含展示方案；求解仍使用原领域文档。界面持续提示该边界。直埋/回填的有限剖视条不是数值远场域；管道开窗和隧道四分之三剖视不是实际开孔。若要参与计算，需要正式领域实体、材料、接口、边界条件、能力预检和人工确认，不能根据外观自动赋予物理参数。

场景类型不同并不意味着现有方法适用范围扩大。排管需要管壁及空气隙换热，沟道/隧道需要壁面与空气或通风边界，桥架需要接触、对流和辐射参数。本实现不把均匀土壤参考热网络用于这些新场景。

## 装配与分解动画

「装配 ⇄ 分解」滑块及「展开演示／合拢演示」用于理解各层和场景构件关系，可暂停或恢复装配。动画是显示位移，不是物理时间、真实施工步骤或热形变。它通过每绘制组的 GPU uniform 更新，不在每帧重建网格或修改原刚体矩阵；拾取与显示剖切使用一致的坐标约定。

温度场绘制组始终保持零分解位移，纯温度场没有装配按钮。系统或应用开启减少动画时停止自动演示，保留手动滑块；进入后台、切换模型和显卡错误时停止动画。原有保存温度历史的时间播放器独立运行，不因结构分解而改变热结果。

## 热分析可视化

`thermal-workbench` 只读宿主校验通过的运行与工件。按明确工况选择，失败/未知工况不借用另一工况数据。工件需要完整摘要；温度历史和场图必须绑定该工况原始场束。校验通过不等于工程审批或标准认证。

- 热网络工件：六个已保存同心等效半径、径向热阻、三相节点温度与土壤影响矩阵。可切换相别和运行/额定点，点击节点查看属性。无效运行点保持缺失，不自动用额定点替代。ΔT/R 标为由保存量得到的展示值；土壤 G 矩阵不是独立串联电阻。
- IEC 额定点：呈现工件里的 T1、T2、金属层、T3、T4 及零项，不补造中间温度或热容。电气电容不能当作热容。
- 动态过程：读取已保存的导体温度时间曲线，支持逐步、播放/暂停、重播、1/60/600/3600 倍速、时间游标、分页原始数据和 CSV。按物理时间间隔播放；不同曲线采样时刻不同时，明确标出保持的上一保存值，不插值、不外推。减少动画设置禁用自动播放但保留逐步与拖动；后台自动暂停。
- IEC 60853 应急曲线：显示允许电流与持续时长，单位 A；不称为实际运行电流或温度历史。
- 保存温度场：将真实二维 x/z 网格放入三维视口，使用固定、不受材质灯光影响的色标。现行工件只有单个时间场快照，不能伪装为随时间变化的三维场。

空间模型优先使用同工况 CAD 工件，否则仅热网络协议可用其保存半径生成显式标注的同心等效结构。0.6 m 轴向剥切是展示长度，不是工程长度，也不虚构绞线。时间播放只更新 ID 精确匹配对象的数值标签，不会把导体峰值铺成外护套温度场。当前不从其他运行借模型，不从缺失工件推导三维温度历史。

### 保存量的物理一致性核对

热网络面板中的「物理一致性核对」检查保存土壤影响矩阵 G 的互易性、正定性，并核对保存表面温升与 Σ GᵢⱼQ′ⱼ，其中 Q′ 为同运行的每相总损耗。按 A/B/C 标识关联径向温度，不因数组显示顺序改变相别。保存值、重构温升和残差同时显示。

这是轻量算术审计，不是新的求解器、标准验证或工程批准。逐相算术容差为 10⁻⁵ K + 10⁻⁶ × 温升幅值，不代表工程允许误差。缺少运行点时保持缺失；不一致只报告，不回写或修正保存结果。没有新增热容、暂态 RC 核心、场景通用换热算法或数值边界条件。

## 状态与交换边界

二维敷设和三维场景共享截面选择；属性与视图按工程、研究及当前/冻结输入隔离。状态放在有界进程内缓存，不写工程数据库，整页刷新后重置。无效草稿、等待新预览及预览失败不会把旧几何展示为当前；历史运行缺场景工件时不重新计算当前模型冒充历史。

浏览器导出 `cablesim-scene.json`，协议 `cablesim.blender-scene/1`，保留完整对象 ID、资产几何键、输入摘要、工程/研究/截面/修订身份和米制实例网格。不包含工程数据库、B-Rep 或求解结果。原显示 mm 顶点和 3×4 行主序位姿的 3/7/11 项除以 1000，旋转不变。交换坐标右手 Z-up，沿 +Y 展示；Blender glTF 导出器完成 Z-up → Y-up，不重复旋转。包络保留 `display-envelope`，B-Rep-only 部件拒绝猜测替代。

交换文件限制 64 MiB，128 对象、512 部件、50 万唯一顶点、100 万唯一三角形、8192 展开实例；拒绝非有限值、越界索引、缺失资产、镜像、缩放/剪切及身份缺项。

```sh
python frontend/src/features/scene/blender/export_scene.py --input /path/cablesim-scene.json --validate-only
blender --background --factory-startup --python-exit-code 1 --python frontend/src/features/scene/blender/export_scene.py -- --input /path/cablesim-scene.json --output /path/scene.glb --save-blend
```

输出路径必须尚不存在；只在独立后台 Blender 进程执行，不清理交互式用户场景。Windows 使用 Blender 可执行文件完整路径。GLB、可选 .blend 与 .manifest.json 保存为仓库外工件；manifest 记录交换/GLB 摘要、输入身份和实际 Blender 版本。extras 中保留对象和几何键用于关联，不代表编辑后仍与工程几何等价。普通查看不需要 Blender。目前仍是单向交换，未实现 GLB 回导、精细环境资产库、自由建模或动态三维求解。

## 验证

```sh
cd frontend
npm test
npm run check:styles
npm run check:visualization
npx playwright install --with-deps chromium
npm run test:visualization-browser
# 仓库根目录
python -m unittest discover -s tests -p test_scene_exchange.py -v
```

`visualization.test.mjs` 验证数据契约拒绝路径、时间处理、温标、几何、拾取及预算；`construction.test.mjs` 验证六类构件、单位和包围盒、空腔、复用、原数据不变性、构件干涉、装配进度及保存物理量核对。

`test:visualization-browser` 顺序执行两个浏览器测试。`verify-visualization.mjs` 用合成数据加载生产 React/WebGL 组件，覆盖相别、时间回放、CSV、主题与错误恢复。`verify-construction.mjs` 使用 **原 AppShell 组件、原 CSS 和导航**，检查六类构件、无每帧显存重分配的装配动画、减少动画、参数拒绝和恢复原模型；业务写入按钮禁用。后者有原外壳但数据仍是合成工况、路由为测试路由，不能充当完整 API、研究业务、精确 OCCT 或用户本机工程的验收截图。

fixture 只由测试导入，不进入应用；截图在 test-results/visualization，不提交 Git。`check:visualization` 是模块及其依赖的严格类型检查，不等于完整应用生产构建。实际执行状态以 CI 日志为准，不由脚本存在推断通过。

CI 保留原后端、Slurm 和发布门禁。Blender 测试需显式 CABLESIM_BLENDER，可用时校验真实 GLB、.blend、对象身份和世界坐标；缺失则跳过，不计为通过。正式发布仍需全量构建、真实工程交互、Windows DPI、硬件显卡性能及原生求解回归。
